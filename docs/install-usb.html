Install from the ATI-OS USB

A bootable installation medium that installs Arch, this configuration and 31 already-compiled AUR packages onto a blank machine. Roughly 20 minutes of unattended work instead of two hours.

Nothing logs you in and nothing starts X. After the install and the first boot, the machine stops at a text console. That is intended. See Logging in.

What ATI-OS is

It lives in installScripts/iso/. The profile is a fork of Arch's own releng archiso profile, kept deliberately close to it — every line that differs has to be re-reconciled when archiso changes, so the diff is branding, the installer, and nothing else.

The saving comes from one thing: pacman-static, espanso, paru and whisper.cpp are compiled once when the ISO is built, not on every machine that installs it. pacman-static alone is about an hour, because it compiles pacman and every dependency statically from source, much of it single-threaded through autotools.

FileWhat it does
aur-repo.shBuilds the 31 AUR packages in a clean chroot into a local pacman repo
build-iso.shStages the profile, the repo and the dotfiles, then runs mkarchiso
test-iso.shA 4-phase qemu test: bootloader, install, boot, filesystem
profile/airootfs/usr/local/bin/ati-os-installThe installer itself

Building the medium

cd installScripts/iso
./aur-repo.sh      # 2-3 h, cached. 31 AUR packages -> a local pacman repo
./build-iso.sh     # 20-40 min. stages the profile, runs mkarchiso
./test-iso.sh      # 1-2 h. boots it in qemu, installs, asserts

Each takes --check to run only its preflight and touch nothing. Do that first — the preflights are the reason a failure costs seconds instead of hours.

aur-repo.sh is separate from build-iso.sh on purpose: rebuilding 31 AUR packages to change a boot-menu label would be absurd, so its output is cached and build-iso.sh only checks for it.

Everything is written under $ATI_ISO_WORK (default ~/ati-os-build), never into the git checkout.

An ISO is a snapshot; rebuild it every six months. The archlinux-keyring baked into it ages out in roughly one to two years, after which it cannot install anything, and its kernel stops recognising new hardware. That is Arch being Arch, not a defect. build-iso.sh is unattended, so the honest version of "always works" is cheap to regenerate, not never expires.

Writing it to a stick

lsblk                      # find the right device FIRST
sudo dd if=~/ati-os-build/out/ati-os-*.iso of=/dev/sdX bs=4M status=progress oflag=sync

dd does not ask. Check lsblk twice. The oflag=sync matters: without it dd returns before the data is actually on the stick.

Starting the installer

Boot the stick, then at the live shell:

ati-os-install

It must run as root. Two other modes exist:

FlagEffect
--checkRuns the preflight and exits. Changes nothing.
--unattendedTakes every answer from environment variables (ATI_DISK, ATI_USER, ATI_PASS, ATI_HOSTNAME, ATI_TIMEZONE, ATI_KEYMAP, ATI_LOCALE, ATI_ENCRYPT, ATI_LUKS_PASS, ATI_DUALBOOT). This is what test-iso.sh drives. It erases the named disk without confirming.

Stage 1: preflight

Before anything is touched, the installer checks six things and refuses if any of the fatal ones fail. Each refusal names the value that failed, rather than saying "requirements not met".

CheckFatal?Notes
UEFI firmware (/sys/firmware/efi/efivars present)Yes"this machine booted in BIOS/legacy mode". The live environment still boots on BIOS machines for rescue work — only installing is refused.
Secure BootNo, but warns loudlyATI-OS installs an unsigned bootloader. With Secure Boot on, the install finishes and the machine then refuses to boot with "no bootable device", which looks like a broken install and is not one. Turn it off in the firmware first.
ClockNoEnables NTP and waits up to 15 seconds. A wrong date makes every package signature look expired or not-yet-valid, and pacman reports that as a signature error rather than a clock problem.
Memory ≥ ~2 GBYesReports the actual MB it found.
NetworkYesPackages are downloaded during the install. If it fails it prints the commands: iwctl station wlan0 connect <network> for Wi-Fi, mmcli for WWAN, ip addr for wired.
At least one diskYes

The medium's age

The preflight reads a BUILD_EPOCH stamp baked into the ISO and decides whether the prebuilt AUR packages can still be trusted. Everything else on an ISO ages harmlessly because it is refetched from mirrors; these binaries were compiled against one particular build day's libraries.

AgeWhat happens
≤ 180 daysUsed. "prebuilt packages are current enough"
181–365 daysUsed, with a warning that a rebuilt ISO is the safer answer
> 365 daysNot used. The AUR set is compiled from source instead — correct, and roughly two hours rather than twenty minutes. The disk floor also rises from 30 GB to 60 GB, because those build trees are large.

If the medium was built without running aur-repo.sh first, there is no prebuilt repo at all, and the installer says so: "no prebuilt AUR repository on this medium".

The questions

These are the real prompts, in the order the installer asks them. Defaults are shown in brackets; pressing Enter accepts them.

1. The target disk

── target disk ──

     /dev/sda   238.5G  Samsung SSD 860
     /dev/sdb    57.3G  SanDisk Ultra

  Disk to ERASE and install onto (e.g. /dev/sda):

The list is real disks only. Loop, ram and nbd devices are excluded by major number and zram by name — on a live medium the squashfs alone adds a loop device, and an early version of this screen showed twenty entries on a machine with one SSD.

The installer refuses the medium you booted from, so picking the USB stick out of the list cannot destroy the installer mid-run. It also refuses a disk with mounted partitions, or one held open by LVM, RAID or an existing LUKS container ("is in use by: lvm") — those make the partition table changes invisible to the kernel until reboot, so the install would proceed against a stale view of the disk.

The dual-boot offer

If the disk already has an EFI partition and at least 25 GB of unused space, you get a choice:

  This disk already has an operating system on it.
    Existing EFI partition: /dev/sda1
    Unused space available: 120G

   1  Keep it and install ATI-OS alongside (uses the 120G of free space,
       you pick which system to boot each time)
   2  Erase the whole disk (everything currently on it is lost)

  Choose [1/2]:

The offer only appears when it can actually work. With an existing ESP but less than 25 GB free, you get a message instead: shrink the other system first — this installer will not resize partitions.

The size floor and the confirmation

A disk smaller than 30 GB is refused outright (60 GB when the medium is old enough that the AUR set gets compiled). A finished install measures about 20 GB, so 25 GB looked fine on paper and left nothing for the package cache, the journal or your own files. Between 30 and 60 GB you get a warning that it works but is tight.

Before erasing, the installer lists what it is about to destroy by name — the partition table, and any operating system os-prober can identify — and then makes you type the path again:

  EVERYTHING on /dev/sda (238.5G, Samsung SSD 860) will be destroyed.
  There is no undo and no partial install.

  Type the disk path again to confirm:

2. Hostname

  Hostname [ati-os]:

3. Username

  Username:

Lowercase letters, digits, - and _, not starting with a digit. It re-asks until the name is valid.

The username is not cosmetic. arch-config keys the host profile off the username. The YAML field is called host: but it holds a username — a quirk of dcli's config schema, documented at length in arch-config.sh. So this answer decides which package set and dotfile profile get applied. It also becomes the name rendered on the boot splash.

4. Password

  Password for <user>:
  Repeat:

Not echoed. Re-asks if empty or mismatched. The same password is set for root.

5. Timezone

  Timezone [Europe/Istanbul]:

The default is guessed from your IP via ipapi.co, with a 5-second timeout, falling back to UTC. An unknown zone aborts rather than silently installing the wrong one.

6. Full-disk encryption

  Encrypt the whole disk?
    Yes: a stolen machine reveals nothing. You type a passphrase at
         every boot, and if you forget it the data is GONE for good.
    Recommended for a laptop. Not needed for a desktop at home.
  Encrypt? [y/N]:

Defaults to no, deliberately. Saying yes asks for a passphrase twice and requires at least 8 characters — LUKS is only as strong as what is typed into it, and a brute-forceable phrase is worse than no encryption because it feels safe. There is no recovery mechanism, by design.

7. Keyboard layout

  Keyboard layout  (see them all with: localectl list-keymaps)
  Keymap [us]:

Validated against localectl list-keymaps and re-asked until it matches. This is asked rather than assumed because the first version of the installer wrote no /etc/vconsole.conf at all: every machine came up with a US console keymap whatever hardware it had, so somebody on an AZERTY or Arabic keyboard would type their own password wrong at the very first login with no way to tell why.

8. System language

  System language  (e.g. en_US.UTF-8, ar_EG.UTF-8, de_DE.UTF-8)
  Locale [en_US.UTF-8]:

Validated against /etc/locale.gen. Whatever you pick, en_US.UTF-8 is also generated, because a surprising amount of tooling assumes it exists and misbehaves confusingly when it does not.

What happens at each stage

After the last question the installer runs without further input. Each stage announces itself with a ── name ── header.

StageWhat it does
partitioningWrites the partition table. If encryption was chosen, cryptsetup luksFormat --type luks2 then opens it as cryptroot. From here on, a failure leaves a half-installed disk — the installer says so plainly, because the recovery is always the same: run it again.
mirrorsMirrors are ranked, not asked about.
package signing keysRefreshes archlinux-keyring from the network first, so the new system's keyring is not limited to what shipped on the stick. Best-effort: with no network it cannot work.
installing the base systempacstrap.
prebuilt AUR packagesCopies the prebuilt packages into the target (pacman inside arch-chroot cannot see /run/archiso), adds them as a SigLevel = Optional TrustAll repo, syncs, and then verifies that the database exists and actually resolves packages. The repo section is removed again at the end, so the installed system is never left with a permanent unsigned package source.
configuring the systemTimezone symlink, hwclock --systohc, locale generation, vconsole.conf, hostname, user creation and passwords.
boot entryA systemd-boot entry titled ATI-OS, with the microcode image if one exists and root= pointing at the real device.
dotfiles and the wizardPlaces the dotfiles (baked into the medium, or cloned if absent).
first-boot setupInstalls and enables ati-os-firstboot.service. Its TimeoutStartSec=0 because the wizard takes 20+ minutes even with everything prebuilt, and systemd's default would kill it partway through. Output goes to journal+console, so somebody watching the screen sees progress rather than an idle login prompt.
doneSyncs, unmounts, closes the LUKS container, and tells you to remove the medium and reboot.

The first boot

The desktop is not installed during the install. It is installed on the first boot, by ati-os-firstboot.service, which runs the same wizard.sh the git-clone route uses — all 46 modules, on screen, roughly 20 minutes. Let it finish before logging in.

cat /var/log/ati-os-firstboot.log       # the whole run
cat /var/lib/ati-os/firstboot-complete  # the wizard's exit status

The marker records the exit status, not merely that the run happened, so a failed first boot does not mark itself done and will retry. To re-run by hand:

cd ~/.dotfiles/installScripts && ./wizard.sh

Read the per-module errors, not the summary card. On a clean install the module that reports a failure is almost never the module at fault. One full disk once presented as five broken modules; one blocked pacman presented as two.

Logging in

There is no autologin and no display manager. The wizard's disable-dm module disables lightdm, gdm, sddm and lxdm on purpose. After the first boot finishes you are looking at a text console with a blinking cursor.

  1. Log in with the username and password you chose.
  2. Type letsgo, or startx if that is not found.

letsgo is a fish function, not a shell alias, so it exists only once the account's login shell is fish. The wizard's login-shell module does that with chsh, but only when fish installed successfully — if it did not, startx is the one that works.

What you still supply

  • GEMINI_API_KEY in ~/.config/secrets.env — the install seeds that file from a template with the key left empty. Everything that uses it degrades rather than breaking when it is absent.
  • Vaultwarden, Simplenote and scrcpy accounts — see Everyday tools.
  • Your own wallpapers, if you do not want the author's collection.

Deliberately not installed by default:

./wizard.sh --only=xmodmap           # Caps-Lock-as-Alt
./wizard.sh --only=dcli-sync-extra   # docker, JDK, printing, qemu

Limits

  • UEFI only. The installed system boots with systemd-boot, and every boot module in this repo (boot-fallback, boot-splash, and boot-splash's root-device verification) is written against it. A GRUB/BIOS path would be a second, untested way to boot.
  • It does not resize partitions. Alongside-install uses free space that is already free.
  • The qemu test cannot touch the GPU path — no graphics hardware, so picom, glx and the window animations are untested by every phase of it.
  • No AMD or NVIDIA hardware, and no 4K panel, has ever run this.
  • The test boots the ISO file, not a real USB stick on real firmware.

An ISO makes the install much easier to run, which means the untested paths start reaching strangers' machines. That is an argument for fixing them, not for reading a green test run as though it had.

Problems with the medium itself are collected under Troubleshooting → The ATI-OS medium.
