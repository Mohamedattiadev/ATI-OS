On this page

    Install from a USB stick

    Make a stick, start the computer from it, answer eight questions. About 20 minutes to install, plus 20 more on the first restart.

    This erases a disk. Everything on the disk you pick is gone and cannot be recovered. Copy anything you care about somewhere else first.

    Exception: if the computer already has another operating system and 25 GB of free space, the installer offers to sit alongside it. See question 1.

    What you need

    A USB stick4 GB or larger. It gets erased.
    The target computerA disk of at least 30 GB, and UEFI mode.
    Internet on itA cable is easiest. Wi-Fi needs two extra commands.
    A second Arch computerTo build the image on.

    There is no file to download. The image is not published anywhere. You build it yourself on a computer already running Arch Linux.

    No second computer? Use the other route: install plain Arch first, then run one command.

    1. Make the stick

    All of this happens on the Arch computer you already have.

    1. cd installScripts/iso

    2. Build the software. Start it and go do something else.

      ./aur-repo.sh

      2 to 3 hours the first time. The result is saved, so a rebuild later is much faster.

    3. Build the image.

      ./build-iso.sh

      20 to 40 minutes. You end up with a .iso file in ~/ati-os-build/out/.

    4. Optional: test it in a fake computer first.

      ./test-iso.sh

      1 to 2 hours. It installs the image and checks the result.

    5. Plug in the stick. Find out what it is called.

      lsblk

      Look for the size that matches. A 32 GB stick shows about 29.8G. The name looks like sdb. Write it down.

    6. Copy the image onto it. Replace sdX with that name.

      sudo dd if=~/ati-os-build/out/ati-os-*.iso of=/dev/sdX bs=4M status=progress oflag=sync

      Check the name twice. This command does not ask "are you sure?" and there is no undo. The wrong name destroys the wrong disk.

      A counter climbs. Wait for the prompt to come back before unplugging.

    Why no download, and why three hours?

    Those hours compile software in advance so your install takes twenty minutes instead of two. The trade, and why an image should be rebuilt every six months, is in How it works.

    All three scripts take --check, which runs only their safety checks and changes nothing. Run that first. It turns a failure that costs hours into one that costs seconds.

    2. Start the computer from it

    1. Plug the stick into the target computer. Turn that computer fully off.

    2. Turn it on and tap the boot-menu key repeatedly.

      Dell, most LenovoF12
      HPF9
      Asus, AcerF12 or Esc
      Anything elseF8, F10, F11, Esc

      A short list of things to start from appears.

    3. Pick your USB stick.

      Listed twice? Pick the UEFI one. UEFI is the modern way computers start. This installer supports nothing else. Pick wrong and it stops with a message rather than half-installing.

    3. The boot menu

    Press Enter on the first entry:

    ATI-OS — Install (x86_64, UEFI)

    The others are a screen-reader version and a memory tester.

    Text scrolls for 15 to 60 seconds. Then a blue ATI-OS logo, a short welcome, and a prompt.

    On Wi-Fi? Connect now. The installer downloads software. A network cable already works. For Wi-Fi type iwctl and follow the prompts. For a mobile modem, use mmcli.

    4. Start the installer

    ati-os-install

    The logo again, then "Arch Linux, and a qtile desktop that is already configured.", then a section headed ── preflight ──.

    5. It checks the computer

    Six checks before anything is touched. Lines marked ok are good. A failure names exactly what is wrong and changes nothing.

    CheckIf it fails
    Started in UEFI modeStops. Turn UEFI on in the firmware settings.
    Secure Boot is offWarns only. Do not ignore it. See below.
    The clock is rightWarns. A wrong date makes downloaded software look untrustworthy, and the error will not say so.
    About 2 GB of memoryStops, and prints what it found.
    Internet worksStops, and prints the commands to connect.
    At least one diskStops.

    Secure Boot. Turn it off in the firmware settings before continuing. Ignore the warning and the install finishes perfectly, then the computer refuses to start and says "no bootable device". That looks like a broken install. It is not one.

    Why those six?

    Each one exists because that failure happened and was hard to diagnose from the error it produced. The clock is the clearest case: a wrong date makes every signature look expired, and the tool reports a signature problem rather than a clock problem. More in How it works.

    6. The questions

    Eight, in this order. Square brackets show the default. Press Enter to take it.

    1. Which disk?

    ── target disk ──

     /dev/sda   238.5G  Samsung SSD 860
     /dev/sdb    57.3G  SanDisk Ultra

  Disk to ERASE and install onto (e.g. /dev/sda):

    Type: the full name including /dev/, such as /dev/sda.

    Means: this disk gets erased and gets the new system. Pick the one whose size matches the computer's built-in disk. Your USB stick is in the list, but you cannot pick it by accident. The installer recognises the stick it is running from and refuses it.

    If the disk already has another system

    With an existing operating system and 25 GB free, you get a choice:

      This disk already has an operating system on it.
    Existing EFI partition: /dev/sda1
    Unused space available: 120G

   1  Keep it and install ATI-OS alongside (uses the 120G of free space,
       you pick which system to boot each time)
   2  Erase the whole disk (everything currently on it is lost)

  Choose [1/2]:

    Type: 1 to keep both, 2 to wipe.

    Means: option 1 uses the free space and leaves your other system alone. You pick which to start each time. The installer will not shrink anything to make room. Free the space yourself first, from the other system.

    The final confirmation

    It lists what it is about to destroy, then asks for the disk name a second time:

      EVERYTHING on /dev/sda (238.5G, Samsung SSD 860) will be destroyed.
  There is no undo and no partial install.

  Type the disk path again to confirm:

    Type exactly what you typed before. A mismatch stops the installer and changes nothing.

    Refusals, and what they mean:

    is the ATI-OS medium you booted fromYou picked the USB stick.
    has mounted partitionsSomething is using that disk right now.
    is in use by: lvm (or raid, crypt)Part of a more complex storage setup. Take it apart yourself first.
    is 20G — ATI-OS needs at least 30GToo small. 30 to 60 GB works but is tight, and it says so.

    2. Hostname

      Hostname [ati-os]:

    Type: anything short with no spaces, or Enter for ati-os.

    Means: the name on your home network. Cosmetic.

    3. Username

      Username:

    Type: lowercase letters and digits. - and _ allowed. Must not start with a digit. Anything invalid and it asks again.

    Means: your account name. You type it at the text screen every time you start the computer. It also becomes the name in big block letters on the startup screen, so ati gives you ATI.

    This answer matters more than it looks

    The software list and settings profile are chosen by username, not by computer name. Two accounts on one machine can want different ones. See How it works.

    4. Password

      Password for <your name>:
  Repeat:

    Nothing appears as you type. No dots, no stars. Empty or mismatched and it asks again. The administrator account gets the same password.

    5. Time zone

      Timezone [Europe/Istanbul]:

    Type: Enter if the guess is right. Otherwise Continent/City, like Europe/Berlin.

    Means: it sets the clock. The guess comes from your connection's apparent location. An unrecognised zone stops the installer rather than silently using the wrong one.

    6. Lock the disk with a password?

      Encrypt the whole disk?
    Yes: a stolen machine reveals nothing. You type a passphrase at
         every boot, and if you forget it the data is GONE for good.
    Recommended for a laptop. Not needed for a desktop at home.
  Encrypt? [y/N]:

    Type: y, or Enter for no.

    Means: everything on the disk is scrambled, and you type an extra password every time you turn the computer on. A thief gets nothing.

    Forget that password and your files are gone permanently. No reset, no recovery. That is the entire point of it.

    Saying yes asks twice and requires at least 8 characters.

    7. Keyboard layout

      Keyboard layout  (see them all with: localectl list-keymaps)
  Keymap [us]:

    Type: Enter for a US keyboard, or the short code for yours: uk, de, fr, tr. Unrecognised codes are rejected and it asks again.

    Means: which letter appears when you press a key. Get it wrong and you will type your own password incorrectly at the first login with no way to see why. That is why you are asked.

    8. Language

      System language  (e.g. en_US.UTF-8, ar_EG.UTF-8, de_DE.UTF-8)
  Locale [en_US.UTF-8]:

    Type: Enter for English (US), or a code in that form.

    Means: the language of menus and messages. English is always set up as well, because a lot of software misbehaves confusingly without it.

    7. What you see while it works

    Nothing left to do. It prints a heading per stage.

    HeadingWhat is happening
    ── partitioning /dev/sda ──Dividing up the disk. The point of no return. Anything failing after this leaves a half-installed disk, and the fix is always to run the installer again.
    ── mirrors ──Finding the fastest download servers.
    ── package signing keys ──Fetching the keys that prove downloads are genuine.
    ── installing the base system ──Basic Linux. The longest download.
    ── prebuilt AUR packages ──Copying in software compiled in advance. This is the time saving.
    ── configuring the system ──Clock, language, keyboard, your account.
    ── boot entry ──Teaching the computer to start the new system.
    ── dotfiles and the wizard ──Putting the desktop settings in place.
    ── first-boot setup ──Arranging for the desktop to build itself on restart.
    ── done ──Finished.
    What are "prebuilt AUR packages"?

    AUR is a large collection of extra software Arch users share. It arrives as source code and has to be compiled on your own computer, which is slow. One package in this set takes about an hour by itself.

    The stick carries 31 already compiled. That is the whole reason this route takes 20 minutes. Why they can be trusted, and why they expire after a year, is in How it works.

    8. Restart

    1. Pull out the USB stick.

    2. Restart the computer.

    Do not leave the stick in. The computer may start from it again and show you the installer a second time.

    9. It builds the desktop

    The desktop is not installed yet. It builds itself on this first restart.

    46 steps scroll up the screen for about 20 minutes. Let it finish. Do not turn the computer off.

    Then you get a black screen with text, waiting for you to log in.

    If it failed, it says so and does not pretend otherwise.

    cat /var/log/ati-os-firstboot.log

    To try again:

    cd ~/.dotfiles/installScripts
./wizard.sh

    Read the individual step errors, not the summary. On a fresh machine the step that reports a failure is almost never the step that caused it. One full disk once showed up as five unrelated broken steps.

    10. Log in

    No login box. Nothing starts by itself. Deliberate.

    1. Type your username, press Enter. Type your password, press Enter.

      The password stays invisible. Normal.

    2. Type letsgo and press Enter.

      The screen flickers. The desktop appears.

    If letsgo is not found, type startx. Two names for one job: letsgo only exists once a particular install step has succeeded.

    Done. What is left

    The desktop works. Three things need an account, and only you can make an account. All three are optional and can wait days.

    ThingGives youWithout it
    Password managerYour passwords on a keyboard shortcutNo password menu. Nothing else changes.
    Note syncingYour to-do list on your phoneThe list still works locally.
    An AI keyExtra suggestions in the translation and flashcard toolsThose tools still work, with one section less.

    Setting each one up is on the other install page. The steps are the same whichever way you installed.

    Two extras are left out because most people do not want them:

    ./wizard.sh --only=xmodmap           # Caps Lock becomes an Alt key
./wizard.sh --only=dcli-sync-extra   # Docker, Java, printing, virtual machines

    For your own wallpapers, drop images into ~/Pictures/Wallpapers/.

    What this cannot do

    • UEFI only. Very old machines cannot. The stick still starts on them for rescue work, but installing is refused.
    • It cannot shrink an existing Windows or Linux install. Free the space first.
    • No AMD or NVIDIA graphics card has ever run this, and no 4K screen. The automated tests run inside a fake computer with no graphics hardware, so a passing test says nothing about how the animations will look on yours.
    • The tests have never used a real USB stick. They start the image file directly.
