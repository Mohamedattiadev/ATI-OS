Keybindings

Everything below was read out of .config/qtile/config.py. If a binding is not here, it is not bound.

The two modifiers

Name hereIn the configX modifier
Supermodmod4 — the Windows key
Altmod2mod1 — the Alt key

Caps Lock is not Alt unless you asked for it. The xmodmap module that repurposes Caps Lock as Alt_L is opt-in and not part of a default install — it has no tap-to-Caps fallback, which is right for one laptop whose Alt key is dead in hardware and merely surprising everywhere else. On a default install, use your real Alt key. To opt in: ./wizard.sh --yes --only=xmodmap.

Workspaces

Nine groups plus a scratchpad. Group S (Anki, Obsidian, the nvimsum window) has no key of its own by design — you reach it via the application bindings.

KeysAction
Super+1…9Switch to that group
Super+Shift+1…9Move the focused window to that group

Inside most modes the plain digits 1…9 also switch groups, so you never get stuck in a chord on the wrong workspace. That applies to rofi, media, resize, draw, hint and cheatsheet mode.

Session and machine

KeysAction
Super+Shift+rRestart qtile. Goes through _smooth_restart, which raises the restart veil and preserves window→group and layout state
Super+Shift+qLogout menu (dm-logout -r)
Super+Shift+F5Refresh the machine without rebooting (reset_PC)
Super+Shift+F6Mirror the Android phone (phone_screen, USB or Wi-Fi)
Super+Shift+zToggle between the top and bottom bar
Super+`Toggle the second system widget box
PrintScreenshot an area straight to the clipboard — the same action as the bar's camera chip
F8Start/stop live voice dictation — types each phrase the instant you pause
F9Start/stop batch voice dictation — whisper.cpp, then xdotool type
Alt+Shift+rReapply the Alt keymap (xmodmap ~/.Xmodmap) safely

Why F8 and F9 rather than F6 and F7. A bare binding is a global grab — qtile takes the key from every application, permanently — so the only question that matters is which keys nothing else wants. Across the row: F1 help, F2 rename, F3 find-next, F5 reload, F6 address bar, F7 caret browsing, F10 menu bar, F11 fullscreen, F12 devtools. F8 and F9 are claimed by essentially nothing. Dictation is a hold-a-thought action: the whole value is starting it before the sentence goes, and a three-key chord is long enough to lose it.

Homerow (mouse-free clicking)

Homerow-style hinting over AT-SPI, so it targets real UI elements with exact bounds rather than guessing at pixels. Each mode has its own Alt binding as well as a letter inside hint mode, because hinting is something you do constantly and a chord costs a keystroke plus remembering you are in a mode.

KeysAction
Alt+SpaceHint and click / switch window
Alt+jScroll mode
Alt+/Search mode
Alt+cCaret mode — vim motions over real text
Alt+Shift+cCaret search — type to find a word, land the caret there
Alt+eEdit a field in nvim, in place

Alt+Space rather than Homerow's own Shift+Space, which would swallow every Shift+Space you type. Caret takes Alt+c because Alt+v is already the CopyQ picker.

Scratchpads

Dropdown windows that appear over whatever group you are on and hide again on the same key.

KeysWindow
Alt+1term1 — kitty
Alt+2term2 — kitty
Alt+5calc — qalculate-gtk
Alt+8WhatsApp
Alt+9DeepSeek
Alt+0ChatGPT

Alt+3 and Alt+4 used to be the pavucontrol and arandr scratchpads. They keep their meaning — audio and displays — but open the audio and display popups instead of a GTK window.

The three web scratchpads are Brave profiles inside the main Brave instance (--profile-directory), not separate browsers. A separate --user-data-dir cannot share anything with the main instance: each one spawns its own GPU process, network service, storage service and three zygotes just to render a page. Three of those totalled ~4.6 GB of a 7.6 GB machine, which is what kept earlyoom killing renderers and showing "Aw, Snap!" in the WhatsApp dropdown.

Hint — Super+Shift+f

The same Homerow actions as the Alt bindings above, discoverable in one place. Each action leaves the mode. It used to persist so actions could be chained, but this chord swallows every other binding on the desktop while it is open — including the ones that reload qtile — and a chord you cannot tell you are inside is indistinguishable from the keyboard having broken.

These four are bound by X keycode (26, 38, 28, 40) rather than by keysym, so they stay on the same physical keys whatever layout is currently active — which is the point, since you press them precisely when the layout is wrong. The letters shown are the US-layout positions.

Only one sheet is ever open at a time — v and f close whichever is showing before opening theirs, which is what makes "the open one" unambiguous for j, k and Tab. Modifier names render as symbols (⇧ Shift, ⌃ Ctrl, ⏎ Enter, ␣ Space) with the legend in the header.

Passthrough — Super+F12

Releases qtile's grabs so an application can receive keys qtile would otherwise take — a VM, a remote desktop, a nested WM. Super+F12 again, or Esc, ends it. Unlike the other modes it does not swallow, so everything else still reaches the application.

Getting this list live

The desktop generates the same list from the config it is actually running, so it cannot drift:

qtile-keys              # every binding with a description, on stdout
rofi_docs keys          # the searchable rofi list
rofi_docs               # the whole documentation menu

Or click the logo in the bar and pick Keybindings. That list is built by parsing config.py's AST rather than with a regex, because bindings nest several KeyChord levels deep — a regex pass found 44 of them and lost every chord prefix, so mode keys printed as a bare letter instead of Super+P , C.

qtile-keys lists only bindings that carry a desc=. Several real bindings deliberately have none — the popup navigation keys, the scratchpads, the language keycodes — so its count is smaller than the tables on this page. This page includes them.
