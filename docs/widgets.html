Widgets and popups

The bar, what each chip does when you click it, the keyboard-driven popups that replaced pavucontrol and arandr, and the veil that hides a qtile restart.

The bar

Two bars are defined and one is shown at a time. Super+Shift+z swaps between the top bar and the bottom bar — only one is ever exclusive.

Everything in the bar is built from a small set of qtile and qtile_extras widgets: GroupBox, TaskList, Chord, Clock, CPU, Memory, Battery, Systray, LaunchBar, TextBox and Spacer, wrapped in a local chip() helper that gives each one the rounded pill decoration.

The chord chip is the one that appears only while a mode is active. It names the mode and lists the keys that mode accepts, and it changes colour per mode. That is what makes a chord discoverable rather than a state you have to remember you are in.

The logo menu

Left-clicking the logo opens rofi_docs. A desktop with this many keybindings, themes and custom tools has a discovery problem, not a terminal-launching problem — so the most prominent click in the bar answers "what can this thing do".

Seven sections, and every one is generated from the live system, because a hand-written menu drifts the moment anything is added, and silently.

How it behaves

  • Esc goes up, not out. Every submenu returns to its parent; only Esc at the top level closes the menu. A menu you have to reopen from the bar after every glance is a menu you stop using.
  • One frame, every section. All of them draw at 614×432 — the same shape dtos-center.rasi gives every other rofi on this system — applied inside pick() so a new section cannot forget it. That frame fixes a 52-column budget, and every row builder is cut to fit it, measured from what rendered rather than derived: the arithmetic says 56 and 56 visibly clipped.
  • Documentation is rendered and read-only. Markdown opens through glow, so you read the document rather than its markup and cannot edit the repo's own docs by accident. Troubleshooting jumps open in nvim -R — readonly mode, not set nomodifiable, which blocks plugins that legitimately write to their own buffers and made fidget.nvim throw on every notification.
  • Troubleshooting rows show the symptom, not the heading. "Rofi" tells you nothing; "yellow wallpaper but rofi selection shows blue/purple" is what you would actually type when it happens. Section rows keep their heading, since they have no symptom of their own.
  • Everything opens in a centred floating window (kitty --class docs-view) at 78% × 80% of the screen, so reading a doc never disturbs the layout.

Maintenance is the only section that acts

It replaced a Commands section that listed every tool in AtiScriptsV1 with its header comment and deliberately never ran any of them — correct, and a reading exercise nobody opened twice, when the scripts are all on $PATH anyway.

What nothing surfaced was the slow rot: .pacnew files never merged, orphaned dependencies, units that failed while you were looking at a splash screen, a package cache growing without bound. So that is what is here, with a live count on every entry, and selecting one merges, removes, prunes or upgrades.

Two deliberate omissions:

  • Pending updates come from the bar's cache (~/.cache/qupdate.json), never from checkupdates, which syncs a private copy of the package databases over the network and would turn a menu draw into a multi-second stall — or a hang with no connection.
  • The orphan entry opens the list, not a bare confirm. "Remove 21 packages?" with no names is a prompt you either rubber-stamp or cancel, and neither is a decision.

Maintenance is Arch-only and says so: it refuses off Arch and names the distro, rather than running pacman commands that do not exist.

Espanso snippets

The snippets in match/base.yml hold no personal data — they shell out to source /etc/environment; echo "$MY_NAME". That is the right design and it has a sharp edge: on a machine where those variables are unset, every one of them expands to an empty string, with no error.

The Espanso section of the logo menu lists which of the 26 variables are set and which are missing, scaffolds the missing keys into /etc/environment (commented, ready to fill), and opens it with sudoedit.

These are qtile_extras popups drawn by qtile itself, not separate applications. They live in .config/qtile/popups/.

Three shared helper modules sit alongside them: _wal_colors.py (palette loading), _scale.py (UI scaling) and _cheatsheet_grid.py (the scrolling card grid the three cheatsheets share).

Every binding for every popup is in Keybindings → Modes and chords.

Why they are popups and not applications. Each one is keyboard-first and closes when its chord ends, so there is no window to manage, no group to put it on and no float rule to write. Alt+3 and Alt+4 keep the keys the pavucontrol and arandr scratchpads used to have.

The cheatsheets

Every binding on a card, with the key hard against the card's right edge, in the same monospace face the rest of the popups use.

The sheets scroll rather than page: j/k move a few rows, Tab/Shift+Tab a screenful, Esc closes, and the header shows how far down you are.

Scrolling is also why the sheets are an ordinary popup size rather than nearly full-screen. Paging tied capacity to size — the only way to show more bindings was to be bigger, and they had grown to 1330×750 on a 1366×768 screen, covering the very window you opened them to ask about. With a viewport that moves, the size only decides how much you see at once.

k does double duty: it opens the qtile sheet when none is up, and scrolls up when one is. Only one sheet is ever open at a time.

Opening a sheet from the logo menu goes through qtile's IPC (open_cheatsheet() in config.py), not xdotool. Replaying the chord could not work: entering Super+Shift+k auto-shows the qtile sheet, so the replayed k toggled it back off and it appeared for a single frame.

HiDPI scaling

Every pixel value in the qtile config was tuned on a 1366×768 14" panel. Copied unchanged to a 15" 4K laptop that is a sliver of a bar with unreadable text — the one thing these dotfiles cannot keep identical by copying files, because the right answer depends on the glass.

ui-scale computes a factor from the primary display's real DPI and writes it to ~/.cache/qtile/ui_scale (per-machine, untracked). qtile multiplies every font size, bar height, icon and margin by it; Xft.dpi carries the same factor into GTK, Qt, rofi and dunst. It runs from .xinitrc on every login, so docking to an external monitor re-scales.

ScreenDPIScale
14" 1366×768 (reference)1251.00
24" 1080p921.00
27" 1440p1091.00
15" 1080p1421.15
14" 1080p1581.25
13" 1440p2271.80
15" 4K2842.25

Physical size, not resolution: a 24" 1080p monitor sits further away and has larger pixels, so it correctly stays at 1.00 rather than shrinking. The factor never goes below the reference — that panel is already small.

ui-scale-toggle        # rofi picker  (also: logo menu -> UI scale)
ui-scale --set 1.25    # pin a value; survives re-detection
ui-scale --auto        # back to detection
ui-scale --show        # detected vs pinned vs active

Nobody has looked at this on a 4K screen. The popups are verified byte-identical at scale 1.0 and proportional at 2.0 — at 2.0 the sheets measure the same 3.6 / 2.0 / 1.4 screenfuls as at 1.0, with pango measuring real glyph extents at both. That is a mathematical proof, not a photograph.

The eww widgets

eww carries the parts that are not qtile popups. Its configuration is in .config/eww/.

WindowWhat it is
onboarding-welcomeFirst page of the tour
onboarding-workspacesWhat the groups are
onboarding-keybindingsThe keys worth knowing first
onboarding-finishLast page
bar-tooltipThe tooltip the bar's tooltip chip opens
csheetA cheatsheet window (cheatsheet/cheatsheet.yuck)

The tour runs once, on the first graphical login after an install, via onboarding-first-run; wizard.sh arms it by writing a stamp file at the end of a successful run. After that it is only reachable from the bar's tooltip chip. onboarding-cheatsheet opens the qtile cheatsheet from inside the tour and hands the tour back its last page when you close the sheet.

eww follows the theme like everything else. SCSS classes cover whole widgets, but the onboarding pages colour individual words inside a label, and a pango <span foreground="…"> can only take a literal — so those hex values used to be hardcoded doomone and stayed doomone on all the other palettes. The palette is now polled from ~/.cache/qtile/current_palette.json and interpolated. The poll interval (30 minutes) is a backstop only: theme-apply reloads or restarts eww immediately after writing.

The restart veil

Super+Shift+r — and any theme change — goes through _smooth_restart, which raises a veil over the transition: qtile/scripts/qtile-restart-veil.py, a separate process so it survives the execv.

It frosts the desktop, shows a card carrying each window's real icon, and reports genuine progress from the incoming qtile — not a timer. It exists because qtile's own boot maps every window from every workspace for ~2 seconds before the startup hook fires, which is unfixable from config alone.

The veil pauses dunst and keeps itself topmost by reacting to root-window restack events, so nothing lands on top of it. It needs python-gobject; without it the reload falls back to a plain restart.

Layout survives the restart

MonadTall ratios and secondary stack sizes save every 3 seconds to layout_state.json; window→group mapping and per-group focus order save to window_group_state.json. Both restore on startup_complete, at +0.6s and +1.6s.

Manually-moved windows stay in the group you chose even though Match rules re-fire on adoption — the client_new hook overrides Match assignment for any window id present in the restored map.
