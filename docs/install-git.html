Install from a git clone

You already have Arch installed — a clean base system, no desktop environment, no display manager. One script builds the rest.

The one command

git clone https://github.com/Mohamedattiadev/Newdotfile-.git ~/.dotfiles \
  && cd ~/.dotfiles/installScripts \
  && ./install.sh

46 modules run end to end with no questions asked, and you land on a complete desktop: qtile, all 22 themes, every font, every widget, and a boot splash carrying your own username.

Set aside an hour or two, and about 25 GB. Nothing is wrong if it seems to sit still — most of that time is one package. pacman-static compiles pacman and every dependency statically from source, and several AUR packages (espanso, whisper.cpp) are built rather than downloaded. It is unattended: walk away and come back.

Then log in and start X

There is no autologin and no display manager. Module 38, disable-dm, disables lightdm, gdm, sddm and lxdm on purpose. Nothing starts X for you.

  1. Log in at the TTY with your username and password.
  2. Type letsgo, or startx if that is not found.

letsgo is a fish function, not a shell alias, so it exists only when the account's login shell is fish. Module 20, login-shell, runs chsh to fish so the TTY matches what kitty already forces — but it skips itself with a message if fish is not installed yet. On such a machine only startx exists.

What letsgo adds over bare startx: it refuses when an X server is already running on :0 and names the VT to switch to, and it removes a stale /tmp/.X0-lock left by an unclean exit — the leftover that otherwise blocks startx with "Server is already active for display 0". It deliberately does not exec, so if startx aborts you can read the error instead of being thrown back to the login prompt.

Back to bash: chsh -s /usr/bin/bash $USER.

Why it never asks anything

install.sh is wizard.sh --yes. Every module runs with stdin closed and the wizard refuses to reach any prompt in that mode. This is a guarantee, not a description — it used to be untrue in two places: the run stopped dead at the very end on a Simplenote password prompt, and any module whose child process asked a question (a git credential, a makepkg confirmation) hung forever behind the spinner, showing nothing but an animation. Both are fixed.

What ./install.sh does on top of running the modules:

  • Auto-bootstraps gum via pacman (~2 s)
  • Keeps sudo alive for the whole run — primed once, refreshed in the background — so long AUR builds do not silently drop package installs when the credential cache would otherwise expire mid-run
  • Auto-skips any failed module, logs it to /tmp/wizard-<id>.err, and lists it in the final summary. dcli sync additionally self-verifies with a dry-run and retries if anything is still missing

The two opt-in modules

Both are valid --only= targets and both are listed (unchecked) in the interactive picker, but neither is ever part of a default run.

idWhat, and why it is opt-in
xmodmapWrites ~/.Xmodmap, repurposing Caps Lock as Alt_L outright, with no tap-to-Caps-Lock fallback. Right for one laptop whose Alt key is dead in hardware, merely surprising everywhere else. Real Alt keys keep working, so on a normal machine this just gives you a third Alt.
./wizard.sh --yes --only=xmodmap
dcli-sync-extradocker, JDK, printing, qemu — see Optional extras. install.sh's promise is a working desktop, not a working workstation.
./wizard.sh --yes --only=dcli-sync-extra

Install options

./wizard.sh                 # interactive: TUI checkbox picker
./wizard.sh --dry-run       # preview every command, touch nothing
./wizard.sh --yes           # same as ./install.sh
./wizard.sh --only=stow,themes,browser-flags       # subset
./wizard.sh --skip=whisper,whisper-fast,piper      # skip heavy downloads
./wizard.sh --yes --only=dcli-sync-extra           # opt-in extras
./wizard.sh --audit         # package drift check (read-only, no sudo)
./wizard.sh --uninstall     # reverse wizard writes (never touches
                            #   packages or downloaded models)
./wizard.sh --uninstall --dry-run  # preview reversals

--only and --skip need the =. --only foo is rejected, not quietly ignored — because an ignored filter means the full live install runs instead, and its second module is pacman -Syu. Unknown flags and unknown module ids fail the same way: exit 2, nothing touched.

Every one of the 48 registered modules has a reversal, even where that reversal is a deliberate no-op (dcli-sync, piper, whisper, whisper-fast, wallpapers — removing those would delete packages, multi-hundred-megabyte downloads, or a ~13×-faster build the uninstaller has no business touching). The wizard refuses to start if a module is ever added without one, because the alternative is discovering it part-way through an uninstall with earlier modules already reversed.

The wizard renders an ASCII banner, grouped module cards (System / Dotfiles / Themes / Browsers / Apps / Media), spinners, progress bars and coloured badges. On failure it shows a red-bordered error tail and prompts retry · skip · quit — unless --yes, which auto-skips.

The three accounts

There are no manual follow-up commands to get a working desktop. What is left are three accounts, and only you can own an account. Do them whenever you like, in any order, days later is fine.

What it unlocksWithout it
SimplenoteThe Super+Shift+S TODOS note syncs to the phone appThe note still works — it is a local file. Only the phone mirror is missing
VaultwardenSuper+p p password pickerNo password menu

Simplenote

Run it without --yes, so it can ask, and run it after your first desktop login — install.sh finishes in a TTY before startx, and this step may need a browser:

cd ~/.dotfiles/installScripts && ./wizard.sh --only=simplenote

It asks for your Simplenote email and password, then proves it worked by pushing the TODOS note for real. On networks that block auth.simperium.com — the login host, which is separate from the reachable note API — it detects that, copies a one-line snippet to your clipboard for the browser console, and takes an access token instead. That is the part that needs a browser.

Once configured the note syncs both ways: every write pushes, and opening the window pulls anything typed on the phone. Merging is the one thing that is never automatic — when both sides changed you get a TODOS.md.remote-<timestamp> to reconcile by hand rather than a silent guess.

Vaultwarden

The installer already started the server on 127.0.0.1:8222 and pointed rbw at it. The account is yours to create:

  1. Open https://127.0.0.1:8222 and register. The s matters — the web vault refuses plain http. The local certificate is already trusted by the browser, because mkcert installs its CA into the NSS store too.
  2. Press Super+p then p and enter that email when asked. rbw prompts for the master password through pinentry and keeps the vault unlocked for 15 minutes.

Details, including the phone app and the Tailscale route: Everyday tools → Passwords.

Gemini

Put GEMINI_API_KEY=… in ~/.config/secrets.env. The install seeds that file from secrets.env.example with the key left empty, so it is already there with instructions in it. chmod 600, and it is gitignored.

Optional extras

The default install deliberately leaves out packages that have nothing to do with the desktop. Skipping them changes nothing about qtile, the themes, the fonts or the widgets. Run this whenever you actually want them:

~/.dotfiles/installScripts/wizard.sh --yes --only=dcli-sync-extra
Containersdocker · docker-buildx · docker-compose
Dev extrasgithub-cli · git-lfs · clang · jdk17-openjdk · uv · ruff
Virtualisationqemu-desktop · edk2-ovmf — only vm-test.sh needs these
Printingcups · cups-pk-helper · system-config-printer
Diagnosticsxorg-server-xephyr (test a qtile config in a nested X) · mesa-utils (glxinfo, for picom trouble on unfamiliar graphics)

The list lives in .config/arch-config/modules/optional.yaml. Add to it and the command above picks the addition up. It is re-runnable: already-installed packages are skipped, not reinstalled.

Post-install tuning

Two interactive scripts, not wired into install.sh because they need a reboot, are per-machine, and prompt before touching anything. Both are idempotent, back up before writing, and print revert instructions at the end.

bash ~/.dotfiles/installScripts/grub_boost.sh    # kernel cmdline: nowatchdog,
                                                 #   quiet loglevel=3, cursor off, i915 GuC
bash ~/.dotfiles/installScripts/service_trim.sh  # audit + disable heavy services

grub_boost.sh refuses rather than guessing. It aborts on a trailing-comment or unquoted GRUB_CMDLINE_LINUX_DEFAULT instead of corrupting it, and prints the offending line. A small number of hand-edited grub files need a manual edit first. That refusal is not a bug.

Trying it without risking a machine

Four layers, cheapest first. Each catches what the one above cannot.

LayerTimeCatches
validate.shsecondsSyntax, qtile config load, hardcoded home paths, unrendered templates
wizard.sh --auditsecondsDeclared packages vs installed, both directions
container-test.sh~3 minA real install as a user who is not you; idempotency
vm-test.sh --unattended~2 hoursX11, systemd, boot, the desktop — the parts nothing else can reach
 
bash ~/.dotfiles/installScripts/validate.sh

bash ~/.dotfiles/installScripts/container-test.sh --check  # verify runtime
bash ~/.dotfiles/installScripts/container-test.sh          # full run
bash ~/.dotfiles/installScripts/container-test.sh --keep   # leave it to poke at

bash ~/.dotfiles/installScripts/vm-test.sh --check         # creates nothing
bash ~/.dotfiles/installScripts/vm-test.sh --smoke         # 2-min headless boot check
bash ~/.dotfiles/installScripts/vm-test.sh --unattended    # the whole thing, no human
bash ~/.dotfiles/installScripts/vm-test.sh                 # fetch ISO, you drive archinstall

--unattended scripts a minimal base system, boots it under UEFI from its own ESP, runs ./install.sh, and then asserts the result: 0 failed modules, validate.sh passing inside the guest, every boot entry's root= matching the guest's real root device, and qtile starting under a headless X server — checking the qtile log for a silent fallback to the built-in config, because qtile cmd-obj -f status answers OK either way. Budget ~2 hours and 60 GB.

Two things to know before running it.

  • It clones from GitHub, so it tests what was last pushed, never the working tree. It refuses to start if the branch is ahead of its remote — do not bypass that guard without meaning to.
  • There is no GPU in the VM, so picom's glx backend, the compositing and the animations are untested there, and a screenshot is not the same as looking at the thing.

Its preflight refuses with the specific number that failed (RAM, disk, KVM, qemu) instead of wedging the host halfway through a 500 MB download.

container-test.sh populates the container from git ls-files, not from the directory and not from a clone — that is exactly what a fresh clone receives, so anything gitignored is correctly absent, and staged work is tested before it is committed. Its idempotency diff warns but never fails, because regenerated files legitimately differ between runs.
