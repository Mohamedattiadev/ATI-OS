Install onto Arch you already have

One command adds the whole desktop to an Arch Linux computer you already have. It asks you nothing along the way.

What you need

Arch LinuxFreshly installed, no desktop on it yet.
25 GB freeOn the disk.
An hour or twoAlmost all waiting. You can walk away.
Internet

It erases nothing. Any settings file it would replace is moved to ~/DefaultConfig/<timestamp>/ first.

1. Run the command

Open a terminal, paste this in, press Enter.

git clone https://github.com/Mohamedattiadev/Newdotfile-.git ~/.dotfiles \
  && cd ~/.dotfiles/installScripts \
  && ./install.sh

It asks for your password once, near the start. Then a logo, then a list of steps, each with a spinner and a tick as it finishes.

What does that command actually do?

Three commands joined. git clone downloads the project to ~/.dotfiles. cd moves into it. ./install.sh runs the installer.

&& means "only if the last one worked". A failed download will not run the installer against nothing.

2. Wait

46 steps run in order. Nothing for you to do.

It will look frozen. It is not. One step compiles a piece of safety software from scratch and can sit there for close to an hour showing nothing. There is no faster way. A couple of other steps compile things too.

Come back in an hour or two.

You get a summary card at the end. You want 46 ok / 0 failed. A failed step is named, along with its error file at /tmp/wizard-<name>.err.

Why it never asks you anything, and why that took work

It is a guarantee, not a description. Every step runs with its input closed off, so it cannot stop and wait for you.

This used to be untrue in two places. The run stopped dead at the end on a password prompt. And any step whose sub-programs asked a question hung forever behind the spinner, showing nothing but an animation. Both are fixed. More in How it works.

3. Log in and start the desktop

No login box. The desktop does not start by itself. Step 38 switches off every graphical login screen it can find.

  1. Log out, or restart. You land on a black screen with text on it — a TTY, a plain text screen with no mouse.

  2. Type your username, press Enter. Type your password, press Enter.

    The password does not appear as you type. Not even dots. That is normal.

  3. Type letsgo and press Enter.

    The screen flickers and the desktop appears.

If it says letsgo: command not found, type startx instead.

Why two different commands for one job?

startx is the standard Linux command. letsgo is a helper this project adds, and it exists only once step 20 has run. That step changes which shell your account uses, and the helper lives inside that shell.

letsgo adds two things. It notices when the desktop is already running and tells you which screen to switch to (Ctrl+Alt+F1). And it clears a leftover file from an unclean shutdown, the one that makes startx refuse with "Server is already active for display 0".

Back to the normal shell: chsh -s /usr/bin/bash $USER. You then lose letsgo.

4. The three accounts

The desktop is finished and working. What is left is three online accounts, and nobody can create an account for you. All three are optional and can wait days.

AccountWhat it gives youWithout it
Vaultwarden — a password managerA pop-up list of your passwords on Super+p then pNo password menu. Nothing else changes.
Simplenote — note syncingYour to-do list also appears in the Simplenote phone appThe list still works. It is a file on your computer. Only the phone copy is missing.

Setting up the password manager

The installer already started the password server on your own computer and pointed the tools at it. Only the account is missing.

  1. Open a web browser and go to https://127.0.0.1:8222

    A registration page appears. The s in https matters — without it the page refuses to load.

  2. Create an account with your email and a master password.

    Nothing here can choose the master password for you, and you must not forget it.

  3. Back on the desktop, press Super+p, then p.

    It asks for your email, once. Then it asks for your master password and keeps the list unlocked for 15 minutes.

The server runs on your own computer and only your computer can reach it. It speaks the same protocol as the official Bitwarden apps, so the phone app and the browser extension both work. Details, including reaching it from a phone, are on The tools you get.

Setting up note syncing

Do this after your first desktop login. It may need a web browser.

cd ~/.dotfiles/installScripts
./wizard.sh --only=simplenote

There is no --yes on that command, on purpose. Without it the step is allowed to ask you questions, which is what you want here.

It asks for your Simplenote email and password, then proves it worked by sending your to-do note for real.

Some networks block the login server while the notes themselves stay reachable. It notices, copies a one-line snippet to your clipboard to paste into your browser, and takes a login token that way. That is the part needing a browser.

Setting up the AI key

Open the file ~/.config/secrets.env and put your key in it:

GEMINI_API_KEY=your-key-here

The file already exists, with instructions inside and the key left blank. Only you can read it, and it is never uploaded.

Optional extras

The install leaves out software unrelated to the desktop. Skipping it changes nothing about how the desktop looks or works. Add it whenever you want it:

~/.dotfiles/installScripts/wizard.sh --yes --only=dcli-sync-extra
Containersdocker · docker-buildx · docker-compose
Extra developer toolsgithub-cli · git-lfs · clang · jdk17-openjdk · uv · ruff
Virtual machinesqemu-desktop · edk2-ovmf
Printingcups · cups-pk-helper · system-config-printer
Diagnosticsxorg-server-xephyr · mesa-utils

Safe to run again. Anything already installed is skipped.

Caps Lock as an extra Alt key

./wizard.sh --yes --only=xmodmap

Not part of a normal install. It turns Caps Lock into an Alt key completely. You lose Caps Lock with no way to get capital-lock back. That is right for one laptop with a broken Alt key and surprising everywhere else. Your real Alt keys keep working, so on a normal keyboard this only gives you a third one.

Doing less than all of it

Mostly for when one step failed and you want to re-run only that one.

./wizard.sh                 # pick steps from a list, with checkboxes
./wizard.sh --dry-run       # show every command, change nothing
./wizard.sh --yes           # exactly the same as ./install.sh
./wizard.sh --only=themes   # run one step (or several, comma-separated)
./wizard.sh --skip=whisper  # run everything except these
./wizard.sh --audit         # compare what should be installed against what is
./wizard.sh --uninstall     # undo the settings changes

The = is required. --only themes with a space is rejected outright rather than ignored. An ignored filter would run the whole install instead, and its eighth step installs every piece of software on the list.

--uninstall reverses settings changes only. It never removes software and never deletes the large downloads.

What has not been tested

  • AMD and NVIDIA graphics cards. Only Intel has been seen working. The driver choice for the other two is reasoned from documentation, not observed.
  • Very high resolution (4K) screens. The sizing maths has been checked and is correct; nobody has looked at the result on a real 4K screen.
  • Some laptop battery indicators, on models that name them unusually.

Proven on a clean test machine: all 46 steps complete, the desktop starts, and it loads these settings instead of silently falling back to a default. On the author's own hardware, also the startup screen and the window animations.

validate.sh cannot tell you the install worked. When the self-check cannot run a check, it marks it "skipped" rather than failing. On a bad install it skips everything and reports success. Trust 46 ok / 0 failed instead.

You can try the whole thing on a throwaway virtual machine first. See How it works.
