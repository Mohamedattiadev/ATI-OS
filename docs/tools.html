Everyday tools

About fifty commands live in .config/AtiScriptsV1/, symlinked onto $PATH at /usr/local/bin by the ati-scripts module. Symlinked rather than copied, so an edit in the repo applies immediately.

qdrop — drop things here, use them later

A lightweight GTK3 daemon that slides in from top-centre, stashes files, text, URLs and images, and lets you drag them back out into any application. It replaced the flatpak it.mijorus.collector. It is themed live from the active palette.

Using it

  • Alt+Shift+d toggles it.
  • Shake the mouse while actually dragging a file, folder or image — any axis, two reversals within 1.2 seconds — and it comes to you. A click-drag carrying nothing (a text selection, a rubber band, panning) is ignored. Shaking while it is already open keeps it open instead of replaying the reveal.
  • Drop a file, text, URL or image in to add an entry. URL text is auto-detected.
  • Drag an item back out to paste into any application.
  • Rubber-band select on an empty area. Ctrl+A, Ctrl+click. Right-click for a menu.
  • Ctrl+V pastes the clipboard — text, files, or a copied image. A web image is raw pixels, so it is saved to ~/.cache/qdrop-images/ and added as a normal file entry.
  • Ctrl+F search. Del remove. Enter open.
  • Text and text files open in a floating alacritty + nvim (clip-view class); image files open in imv.
  • It auto-hides 8 seconds after the pointer leaves, paused while dialogs or menus are open.

Files and IPC

.config/qtile/scripts/qdrop.pyDaemon, IPC and widget
.config/qtile/scripts/qdrop_watch.pyXInput2 raw-event shake detector. Firing also requires a real XDND drag in flight, which is why a plain click-drag is ignored. --debug logs each decision; --any-drag disables the drag requirement
.config/qtile/scripts/qdrop_test.pyPure and live tests: helpers, IPC, shake detection, and a stubbed-GTK suite over the open/close state machine
 
qdrop.py --show | --hide | --toggle | --add-text TXT | --reload | --status

Over a Unix socket at /tmp/qdrop-$UID.sock. Persistence lives at ~/.cache/qdrop.json; a palette reload triggers itself from an mtime poll. Both the daemon and the watcher are launched from autostart.sh at login. Measured cost: 0% CPU idle, ~90 MB combined RSS.

qupdate — updates and installs, no terminal

Click the updates chip in the bar. A floating GTK3 daemon with two tabs.

Updates tab

  • Lists pending pacman and AUR packages, from a parallel paru -Qu plus paru -Qua.
  • Cache-first render from ~/.cache/qupdate.json, so it opens instantly; revalidation runs on a background thread.
  • Per-package checkbox, a PKG/AUR badge, and oldver → newver.
  • Refresh / All / None / filter.
  • Footer: Update selected (paru -S --needed) or Full upgrade via the tool combo — which defaults to dcli sync, so timeshift snapshots and arch-config module state stay in sync.
  • Run in background means no terminal: notify-send on success or failure, and a log at /tmp/qupdate-$UID-run.log.

Install tab

  • Searches the official repos (pacman -Ss) and the AUR (paru -Ssa) with a 350 ms debounce. Repo search is used for common queries so paru's "too many results" cap does not apply.
  • Deduped and sorted: exact match → prefix → substring, repo before AUR, not-installed first, shortest name.
  • Rows show name, badge and description, with an installed marker when present.
  • Install selected runs paru -S --needed <pkgs>, in a terminal or in the background.
qupdate.py --show | --hide | --toggle | --refresh | --status | --daemon

Over /tmp/qupdate-$UID.sock. It is palette-themed (polling current_palette.json's mtime every 3 seconds) and autostarted hidden at login.

Passwords

Super+p then p opens a rofi picker over your vault. Enter copies the password and wipes the clipboard 30 seconds later.

The hint line advertises only the three you reach for — ↵ copy, Alt+n new, Alt+x delete — but the full set is bound:

KeyAction
↵Copy the password (clipboard cleared after 30s)
Alt+uCopy the username
Alt+tCopy the TOTP code
Alt+oOpen the entry's website
Alt+aType the password into the window that had focus — never touches the clipboard
Alt+nNew entry (generate a 24-character password, or type your own)
Alt+eEdit — choose password or username
Alt+xDelete an entry
Alt+sForce a sync

Behind it is Vaultwarden, a Rust reimplementation of the Bitwarden server, running on 127.0.0.1:8222 and read through rbw. Vaultwarden speaks the Bitwarden API, which is the whole point: the official Bitwarden phone apps sync against it, so there is no bespoke mobile client to trust.

Browser extension

  1. Install the Bitwarden extension from the store.
  2. Open it and, before logging in, click the ⚙ cog (top-left of the login screen) → Self-hosted environment.
  3. Server URL: https://127.0.0.1:8222 — the s matters.
  4. Save, then log in with your email and master password.

Nothing extra is needed: the local certificate is already trusted by the browser, because mkcert installs its CA into the NSS store too.

From your phone

The server listens on loopback only, deliberately. Do not open port 8222 to your network or the internet.

Two things make a plain LAN address useless, and both are worth knowing before you try:

  • The Bitwarden app refuses plain HTTP outright — the web vault has a hard url.startsWith("https://") check with no localhost exception.
  • Since Android API 24, apps do not trust user-installed CAs. Putting the mkcert root certificate on the phone still leaves the app rejecting the connection. This is the step that eats an evening.

Tailscale sidesteps both: tailscale cert issues a publicly trusted certificate for a *.ts.net name, so the app accepts it with nothing installed, and only your own devices can reach the server.

sudo tailscale up                                     # opens a login URL
# enable MagicDNS + HTTPS Certificates in the admin console, then:
./wizard.sh --yes --only=vaultwarden-phone

That module enables tailscaled and publishes the proxy. It uses tailscale serve rather than rebinding Vaultwarden, because one process can only bind one address — rebinding to the tailnet IP would take 127.0.0.1 away and break both rofi_pass and the browser extension. The proxy terminates TLS with the tailnet's own certificate and forwards to the local listener, so nothing is exposed to your LAN.

It stops with a hint if either piece is missing, because neither can be done from the machine: sudo tailscale up needs a browser and your account, and MagicDNS and HTTPS Certificates both have to be on at login.tailscale.com/admin/dns — without them tailscale cert answers "your Tailscale account does not support getting TLS certs".

On the phone: install Tailscale and sign in with the same account, install Bitwarden, open it and before logging in tap ⚙ → Self-hosted environment, and set the server URL to https://<host>.<tailnet>.ts.net:8222.

A laptop is not an always-on server. With the lid shut, the phone can still read the vault it has already cached, but it cannot sync or save new entries until the laptop is back. If that matters, move Vaultwarden to something that stays on — a Raspberry Pi or a small VPS — and repoint rbw config set base_url. Nothing else changes.

Android screen mirroring

Super+Shift+F6 puts the phone on screen, with mouse and keyboard control back to it. It works over USB or Wi-Fi; the script picks whichever is available and prefers the cable.

The first time

Turn on Wireless debugging on the phone once — Settings → Developer options → Wireless debugging. It survives reboots, so this is genuinely one time.

Then press the key. A rofi window opens with a QR code and a text field. Either scan the QR with the phone (Wireless debugging → Pair device with QR code), or tap Pair device with pairing code and type the 6 digits into the same window. Whichever finishes first wins. After that, pairing is remembered and the key goes straight to the mirror.

Why the script exists

Arch's android-tools is built without mDNS. adb mdns services answers unknown host service, so adb cannot find a wirelessly-debugging phone by itself — every guide that says "adb just finds it" is wrong on this distro. The address and port are also both random, and the connect port changes on every phone reboot.

phone_screen reads the phone's own mDNS announcement through avahi-browse and hands adb a plain host:port. That is why the scrcpy module enables avahi-daemon and opens 5353/udp in ufw.

Speed

Wi-Fi is the bottleneck, not the laptop. Measured on this machine, ping to the phone averaged 53 ms with 16 ms of jitter — worse than two frames at 30fps before anything is encoded. Over Wi-Fi the script caps the stream (-m 720 --max-fps=30 -b 3M) to spend what headroom exists on latency rather than detail; over USB it raises the ceiling (-m 1280 --max-fps=60 -b 12M).

Plug in a cable if the picture matters. It is not a marginal upgrade.

Sound comes out of the laptop: --audio-source=output forwards the whole device output and mutes playback on the handset. It is a second, separately-buffered stream and costs some latency — --no-audio is the way back to the lowest-latency picture, and --audio-buffer is the knob if it crackles.

Pressing the key again focuses the existing mirror rather than starting a second one. Two scrcpy processes against one phone means two decoders and two audio streams competing for the same Wi-Fi budget, which looks exactly like the link being slow.

Window size and rotation

PHONE_SIZE (percent of usable height, default 92) tunes it: PHONE_SIZE=100 phone_screen. Portrait has no slack to give — a ~9:20 handset at full height is only ~325px wide on a 1366×768 panel — so 100 is the ceiling there. Landscape is capped separately at 60% of screen width.

Turn the phone sideways and scrcpy resizes its own window, keeping the top-left corner fixed while it grows — which, anchored to the right edge, walks the window straight off the screen. Two things stop it: at launch, placement reads the current rotation from dumpsys window displays (cur=WxH) rather than wm size, which reports the physical panel and never changes; mid-session, a small watcher samples the window geometry once a second and nudges it back inside the usable area. The watcher is a poll because qtile's float_change hook fires zero times for a floating window resized from outside qtile — it tracks floating state, not geometry.

Voice dictation

KeyToolModel
F8voice_dictate_live — types each phrase the instant you pauseWhisper base.en
F9voice_dictate — press to start, press again to stop and paste the transcriptWhisper small.en

Both run on whisper.cpp locally — nothing is sent anywhere. The batch path is whisper-cli plus sox plus xdotool; the live path is whisper-stream in VAD sliding-window mode, with voice_dictate_live_typer.py reading its block output and typing only the new words of each block.

The models are downloaded by the whisper module (~630 MB). The whisper-fast module then rebuilds whisper-cli and whisper-stream optimised and patched, shadowing the AUR binaries via /usr/local — the AUR package is roughly 13× slower unoptimised, and does not build whisper-stream at all. That module warns and skips rather than failing if it cannot rebuild, since it is a speedup and not a requirement.

Mic gain. WirePlumber resets capture gain to clipping levels on every login, which makes dictation transcribe garbage and looks like a model problem. The mic-gain module enables fix-mic-gain.service, which reasserts it.

Notes and todos

TriggerWhat
Super+Shift+sOpen or focus sum.md in kitty, globally
Alt+p or the clock chipclock_popup — today and this week's plans and todos
Super+P then trofi_todo
Super+P then odm-note -r — store and copy notes

The TODOS note syncs to the Simplenote phone app once you have configured the account (./wizard.sh --only=simplenote, without --yes). Every write pushes and opening the window pulls. Editing offline on either side is safe — the pull doubles as the retry for an unsent write, and a push checks the note before overwriting it. Merging is the one thing that is never automatic: when both sides changed you get a TODOS.md.remote-<timestamp> to reconcile by hand rather than a silent guess.

Updating safely

Use dcli update or safe-update, not a bare pacman -Syu. Three layers guard it:

  1. A pacman PreTransaction hook (pacman-preflight) that refuses when / is too full. It fires for any tool, so it cannot be bypassed.
  2. A dcli pre_update hook that blocks on low space, snapshots stored on the root device, or an inconsistent package database.
  3. A post_update hook that finds AUR packages broken by a library soname bump and puts the rebuild command straight on your clipboard (post-update-notify).

The recovery ladder, in order: downgrade → the LTS fallback kernel at the boot menu → the LTS rescue entry (same kernel, full-module initramfs) → pacman-static from the Arch ISO → a Timeshift restore from /home.

The wizard module boot-fallback writes both LTS boot entries — the linux-lts package on its own ships none, so without it the rescue kernel is installed but unreachable.
