Writing a plugin

A plugin is one directory. Put it in ~/.config/ati-plugins/ and it is installed — there is no register step, no list to add yourself to, and no file of someone else's that you have to edit.

What a plugin can add

Five things, and you pick any subset of them. A plugin that is only a colour scheme has one folder in it. A plugin that is only a command has one folder and one file.

You put this in your pluginAnd you get
bin/Commands you can type anywhere, like the built-in ones
binds.confKeyboard shortcuts
menu.jsonEntries in the Super+? menu
theme/A colour scheme in the theme picker
qml/A panel or popup on screen
[service] in the manifestSomething that runs in the background from the moment you log in

The only required file is the manifest.

Your first plugin

  1. Make the directory. The name you choose here is the plugin's name everywhere else.

    mkdir -p ~/.config/ati-plugins/pomodoro/bin

  2. Write the manifest at ~/.config/ati-plugins/pomodoro/plugin.toml:

    name        = "pomodoro"
description = "A work timer that mutes notifications while running"
version     = "1.0.0"
depends     = ["notify-send"]

    name has to match the directory name. Everything else is optional, but depends earns its keep: it is what lets ati-plugin doctor tell somebody why your plugin does nothing on their machine instead of leaving them to guess.

  3. Put an executable in bin/, and make it executable:

    chmod +x ~/.config/ati-plugins/pomodoro/bin/ati-pomodoro

  4. Run ati-plugin sync.

    ✔ synced 1 plugin(s): 1 command(s) linked — and ati-pomodoro now runs from any terminal.

The three commands

CommandWhat it does
ati-plugin listEvery plugin, its version, and which of the five surfaces it uses
ati-plugin syncMakes it all live. Run it after adding, changing or deleting a plugin
ati-plugin doctorEverything that is wrong, in one place. Exits non-zero, so a script can use it

sync is the only one that writes anything. It is safe to run at any time and as often as you like: it works out the whole picture from what is on disk and rebuilds, so running it twice does exactly what running it once did.

Removing a plugin

Delete the directory and run ati-plugin sync. That is the whole procedure.

There is no uninstall step to forget, because a plugin never edits anything outside its own folder. sync remembers what it created last time and removes it before it builds again, so the command it put on your PATH and the shortcut it added both go when the folder does.

Three rules worth knowing before you write one

Your names cannot shadow anything

If your bin/ holds a file called ati-menu, it will not be linked — the built-in command of that name keeps working. The same goes for a keyboard shortcut the desktop already uses: doctor names the clash and the shortcut stays with the base config.

This is deliberate and it is not negotiable. A plugin that could quietly take over Super+Space would produce the symptom "my launcher stopped working" a week after you installed it, with nothing on screen connecting the two.

You can override the desktop, but not the person using it

A menu.json entry with the same key as a built-in one replaces it. But the file you hand-edit, ati-menu-extensions.json, is merged last and wins over every plugin. A colour scheme works the other way round: the shipped ones win, so a plugin cannot redefine what doomone means on a machine that already had it.

A broken plugin is skipped, not fatal

If your manifest does not parse, your plugin is listed with the reason and nothing else happens. If your qml/main.qml has an error in it, it is skipped by name in the log and every other plugin still loads. The desktop is not allowed to break because something in this folder did.

If you want something running in the background

Some things are not a command you run, they are a program that sits there: a timer, a watcher, something that puts a notification up every so often. Say so in the manifest:

[service]
exec = "ati-adhkar"

ati-plugin sync starts it, and it starts again by itself at every login. You do not add a line to any autostart file — there is nowhere to add one, on purpose.

It runs as a supervised background service, not as part of the desktop starting up. That distinction is the reason this is allowed at all: a plugin that ran inside the startup sequence could hang it, and then the desktop would not come up. This one cannot — if it crashes, it is a stopped service and nothing else. You can see it and stop it like anything else on the system:

$ systemctl --user list-units 'ati-plugin-*'
  ati-plugin-adhkar.service   loaded active running

$ systemctl --user stop ati-plugin-adhkar.service

Your plugin's own bin/ is on the service's PATH, so it can call its own helper scripts by name.

Plugins that came with the desktop

Some plugins ship with ATI-OS itself and live in the repository rather than in your own folder. ati-plugin list marks them [shipped]. They follow exactly the same rules as yours — adhkar, the remembrance notifier, is one, and it is a plugin.toml, a bin/ and a [service] line like any other.

If you want to change one, make a plugin of your own with the same name in ~/.config/ati-plugins/. Yours wins, and the shipped one is ignored.

If you want to draw something

qml/main.qml is loaded once. It gets no window and no parent — if you want something on screen, declare your own PanelWindow inside it; if you only want to run logic, declare none.

It is hosted by the menu process, not by the bar. That is on purpose: there are two bars and switching between them stops one and starts the other, so anything hosted by a bar would disappear when you switched. The menu process runs in both, and because it is a separate process, a plugin that crashes it cannot take your bar with it.

When something is not working

Run ati-plugin doctor. It checks the manifests, the programs your plugin says it needs, name clashes against both the built-in commands and other plugins, keyboard shortcut clashes against the desktop's own, and whether the generated files are up to date.

$ ati-plugin doctor
✖ pomodoro needs notify-send
✖ rude: bin/ati-menu shadows an AtiScriptsV1 command of the same name
✖ rude: (no mod) F9 is already bound by binds.conf
✖ doctor: problems above

If a plugin is not listed at all, check that the directory does not start with a dot and that it contains a plugin.toml.
