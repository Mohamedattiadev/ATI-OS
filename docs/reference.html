How to edit a settings file safely

  1. Edit the file.

  2. Check it before you rely on it:

    bash ~/.dotfiles/installScripts/validate.sh

    A couple of seconds. It loads the window manager settings for real rather than reading them, so a mistake is caught here instead of by the desktop disappearing.

  3. Apply it:

    Super + Shift + r

    The desktop restarts behind a frosted overlay. Your windows stay exactly where they were.

Why step 2 matters. An error in the settings file does not produce an error message. The window manager silently loads its own plain built-in settings instead. The failure looks like your desktop turning into a stranger's, with nothing explaining why.

Why editing the repo changes your desktop

The files in ~/.config/ are not copies. They are links back into ~/.dotfiles/.config/. Editing either path edits the same file.

So:

  • You can edit whichever path you find easier.
  • There is no "apply my changes" copy step to forget.
  • Your changes join the project's history, so you can see what you changed and undo it.

stow_script.sh sets this up. It runs during the install, and you can run it again by hand:

bash ~/.dotfiles/installScripts/stow_script.sh

Nothing is overwritten. Any file it would replace moves to ~/DefaultConfig/<timestamp>/ first.

The details of what does and does not get linked

The project's own documentation is excluded by pattern, so it does not end up scattered in your home folder. Same for the images, the install scripts and this manual.

Full reasoning, including the two ways a naive setup went wrong, in How it works.

Adding and removing software

The software list is written down in files rather than being whatever happens to be on the computer. A second computer can be made identical, and you can see what you added.

  1. Open the right file in ~/.dotfiles/.config/arch-config/modules/ and add or remove a line.

    FileWhat belongs in it
    apps.yamlEveryday applications
    dev.yamlProgramming tools
    media.yamlSound and video
    fonts.yamlFonts
    system-tools.yamlCommand-line utilities
    wm.yamlThe desktop itself
    network.yamlWi-Fi and Bluetooth
    optional.yamlThings installed only on request — Docker, Java, printing

  2. Apply it:

    dcli sync

    A snapshot is taken first, so a bad change can be undone.

  3. Once the computer is working properly, save the change:

    cd ~/.dotfiles
git add .config/arch-config
git commit -m "add something"

To see whether what is installed matches what is written down:

~/.dotfiles/installScripts/wizard.sh --audit

Read-only. It changes nothing and needs no admin permission.

Three of these files are deliberately never applied automatically

The three graphics files, one per manufacturer. The startup screen's file. The optional extras. Each is correct only in particular circumstances, so something else decides when to use them. See How it works.

Undoing things

To undoRun
All the settings changes the installer made./wizard.sh --uninstall
Just one step./wizard.sh --uninstall --only=<name>
See what an undo would do first./wizard.sh --uninstall --dry-run
The startup screen specifically./wizard.sh --uninstall --only=boot-splash
Caps Lock behaving as Alt./wizard.sh --uninstall --only=xmodmap
Going back to the normal shellchsh -s /usr/bin/bash $USER
A bad software updateRestore a snapshot — see the recovery steps

Undo never removes software and never deletes large downloads like the dictation models or the wallpapers. Settings changes only.
