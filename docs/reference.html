How stow works here

installScripts/stow_script.sh wraps GNU stow. It is run by the wizard's stow module, and it can be run by hand on any Linux — it is the one path that deploys the configuration half of this repo without pacman.

bash ~/.dotfiles/installScripts/stow_script.sh

Four things it does that plain stow . does not:

  1. It derives its own location. DOTFILES_DIR comes from where the script actually lives, not from an assumed ~/.dotfiles. The repo is routinely checked out elsewhere — a clone under a different name, a git worktree, /tmp during container tests — and hardcoding the path made it silently stow a different checkout than the one it was run from. DOTFILES_DIR can still be overridden explicitly.
  2. It backs up before it links. Anything it would overwrite moves to ~/DefaultConfig/<timestamp>/. Only regular files are moved at the top level: an existing directory is not a stow conflict — stow just descends into it — and moving a real ~/.claude out from under the user would be destructive rather than helpful.
  3. It creates ~/.config first, so stow descends into it rather than folding the whole directory into a single symlink, which would pollute the repo with every future application's config.
  4. It honours .stow-local-ignore, and refuses to back up anything that file excludes — moving a file stow was never going to link just relocates the user's data for nothing.

Packages: dcli and arch-config

Every pacman and AUR package is declared in YAML and reconciled by dcli. Change a module, run dcli sync, and the system converges. timeshift-autosnap snapshots on every sync, so a broken update is a one-command rollback.

arch-config/
├── config.yaml                 pointer to the active host
├── hosts/ati.yaml              enabled_modules + host packages
└── modules/*.yaml

To add or remove a package: edit the right modules/*.yaml, run dcli sync, then commit once the machine is verified working.

cd ~/.dotfiles
git add .config/arch-config
git commit -m "arch-config: <change>"

host: means USERNAME, not hostname. It reads like a bug and cannot be renamed: host: is dcli's config schema, not this repo's, and the string is baked into the dcli-arch-git binary — renaming it would stop dcli finding its configuration. The behaviour is also the one wanted: these are per-user package sets and dotfile profiles, and two accounts on one machine legitimately want different ones. It is documented in place at arch-config.sh so the next reader does not "fix" it.

Update hooks

pre_updatescripts/pre-update.sh — gates dcli update on free space and on timeshift snapshots not living on the root filesystem. It refuses (a non-zero exit aborts the update before anything is downloaded); it does not repair
post_updatescripts/post-update.sh — finds AUR packages broken by a library soname bump and puts the rebuild command on your clipboard
behavioralways, so it can never be skipped by accident. A safety check you can click past is not a safety check

pacman-static is roughly an hour of any fresh install, on its own. It compiles pacman and every dependency statically from source, much of it single-threaded through autotools. It is a genuine safety net — the day it matters is the day nothing else can install anything — but it is the single biggest cost in a fresh install. The trade is documented at the declaration in system-tools.yaml; moving it to optional.yaml is a one-line change if faster installs are worth more than the net.

Auditing drift

./wizard.sh --audit    # declared vs installed, both directions. Read-only, no sudo

Packages that are installed but deliberately undeclared live in audit-ignore.yaml, with the pacman -Rns command recorded next to them — uninstalling from a working machine is the owner's call, not the audit's.

The test layers

LayerTimeCatches
validate.shsecondsParses every tracked shell, Python, fish and YAML file, loads the qtile config for real, greps for hardcoded home paths, checks every .tmpl has a renderer, and runs a full wizard dry-run
wizard.sh --auditsecondsDeclared packages vs installed, both directions
container-test.sh~3 minA real install as a user called tester: a path that only resolved because $HOME happened to be the author's own home directory, an unrendered @HOME@ template, a step that is not idempotent, a module YAML that no longer parses
vm-test.sh --unattended~2 hX11, systemd, boot, the desktop

The githooks module symlinks a pre-commit hook that runs validate.sh plus --audit — the two fast layers only, because a hook that takes three minutes gets --no-verify'd within a week.

validate.sh exists because qtile falls back to its stock config on an error, so the failure mode is a desktop that looks like a stranger's rather than an error anyone sees.

What no layer covers. The container has no X server, no systemd and no PCI bus. The VM has no GPU, so picom, compositing and the animations are untested there — a green phase-D run must not be read as though it covered them. Nothing anywhere covers AMD, NVIDIA or a HiDPI panel.

Things that look like bugs and are not

Recorded in plan_found-but-not-fixed.md precisely so nobody re-breaks them.

  • host: keys off the username, not the hostname. See above.
  • grub_boost.sh refuses rather than guessing. It aborts on a trailing-comment or unquoted GRUB_CMDLINE_LINUX_DEFAULT instead of corrupting it, and prints the offending line.
  • wizard.sh hard-fails on non-Arch in preflight. Deliberate. Loosening the gate would let pacman-only steps run on a distro that cannot satisfy them.
  • boot/*.conf hardcode a PARTUUID and intel-ucode.img. They are reference copies that are never installed; the wizard generates live entries from /proc/cmdline, bootctl --print-esp-path and whichever microcode file exists.
  • config.py's font="Ubuntu Bold" despite fc-match "Ubuntu Bold" answering Noto Sans CJK. libqtile builds via FontDescription.from_string(f"{font} {size}px"), and pango parses that to family Ubuntu plus weight 700. The set_family() path that would break it is only reachable from the set_font command, which this config never calls.
  • container-test.sh's idempotency diff warns but never fails. Regenerated files legitimately differ between runs.
  • speed_boost.sh's zram ceiling. zram-size = min(ram, 8192) is zram-generator's own expression and already scales with RAM; only the 8 GB ceiling is a fixed number, and it only applies on machines larger than the one it was written on, where an 8 GB zram is a defensible cap anyway. swappiness=180 and page-cluster=0 are the standard pairing for compressed swap.
  • copyq_rofi's one remaining /tmp path is a mktemp — unique, and mode 600.

Known shellcheck false positives

  • SC2209 at ui-scale:55-56 (MODE=set — set as a string value)
  • SC2016 at container-test.sh:100 (a single-quoted in-container script, intentional)
  • SC2015 at scripts/pre-update.sh:70,142 (A && B || C where B is an always-succeeding printf)
