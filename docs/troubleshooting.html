Troubleshooting

Find what you are seeing in the headings below. Every problem here is real, with the cause and the fix.

The first five minutes

I get a black screen with text on it, and nothing happens

Nothing is wrong. There is no graphical login screen, and the desktop does not start itself. Deliberate.

  1. Type your username, press Enter. Type your password, press Enter.

    The password does not appear as you type. Not even dots. Keep going.

  2. Type letsgo and press Enter.

If that says letsgo: command not found, type startx. Same job. letsgo only exists once a particular install step has succeeded.

It says "Server is already active for display 0"

A previous session left a marker file behind. letsgo clears it for you. With startx, do it by hand:

  1. First check whether the desktop is genuinely already running:

    pgrep -x Xorg

    If that prints a number, the desktop is running. Switch to it with Ctrl+Alt+F1 and stop here.

  2. If it printed nothing, remove the leftover and try again:

    rm -f /tmp/.X0-lock
startx

The desktop never appeared after installing from USB

The desktop builds itself on the first restart, not during the install. About 20 minutes, with progress on screen. A failure is reported, and it retries next time rather than pretending it worked.

cat /var/log/ati-os-firstboot.log

To run it again yourself:

cd ~/.dotfiles/installScripts
./wizard.sh

The desktop starts but looks completely plain

No colours, no bar, nothing like the pictures. The settings file had an error, so the window manager fell back to its built-in default. Silently.

bash ~/.dotfiles/installScripts/validate.sh

That loads the settings for real and reports the error. Also worth reading:

grep -i config ~/.local/share/qtile/qtile.log | head

The self-check says everything passed, but nothing works

validate.sh marks anything it cannot check as "skipped" and still reports success. On a bad install it skips everything and finishes green.

Trust the installer's own count: 46 ok / 0 failed.

One rule before you start digging

The step that reports a failure is almost never the step that caused it.

One full disk once showed up as five broken steps, 32 steps after the real cause. One blocked software transaction showed up as two.

Read the individual error files, not the summary card:

ls /tmp/wizard-*.err
cat /tmp/wizard-<name>.err

That is what separated five real causes from twenty-two symptoms.

During the install

It finished, but some software is missing

The software sync prints "✓ Packages synced successfully" whatever happened above it. Check yourself:

dcli sync --dry-run

That lists anything still missing. Three causes have produced it:

  1. Admin permission expired part-way through. Things were built and never installed. The installer now keeps it alive for the whole run.
  2. Two pieces of software conflicted. It is one transaction, so everything in that round failed, not just the two that clashed.
  3. One package's build tools were not ready. Breaks only the packages needing them.

It ran out of disk space

About 25 GB installed, and more while working. This once showed up as six unrelated steps reporting "No space left on device", 32 steps after the cause.

On an older computer, clear the build cache:

yay -Sc

It stopped because of unread news

Arch has a tool that blocks software changes until the distribution's announcements are read. It installs itself part-way through, and a new machine always has unread ones.

The installer handles it. It has to be done as the administrator. Doing it as yourself has no effect, which is a confusing 20 minutes if you go looking.

Other install problems

All covered in the full troubleshooting file, with cause and fix:

  • gum: command not found on a brand new Arch
  • A step sits with no output for a very long time (this is usually normal — see above)
  • The install hangs near the end with the spinner still turning
  • Your password is rejected repeatedly even though it is correct
  • The admin-without-password step reports success and you still get asked
  • The laptop still sleeps when you close the lid
  • The install stops because you already have a ~/.tmux.conf
  • On an AMD computer, the desktop is very slow and the graphics step "failed"

The USB stick

The computer will not start from the stick at all

Three things, in this order:

  1. Pick the UEFI entry. The boot menu usually lists the same stick twice. Choose the one that says UEFI.

  2. Turn Secure Boot off in the computer's firmware settings.

  3. Check the copy actually finished. Copying to a USB stick can return before the data is really there.

    sha256sum -c ati-os-*.iso.sha256

"No bootable device" after the install finished

Almost always Secure Boot. The installer uses an unsigned startup program, which Secure Boot refuses to run. The install completes perfectly, then the computer will not start. It looks exactly like a broken install.

Turn Secure Boot off and start again. Nothing needs reinstalling.

The installer refuses to start

Each refusal names the exact thing that failed:

What it saysWhat to do
booted in BIOS/legacy modeRestart and choose the UEFI entry, or turn UEFI on in the firmware settings
${N}G — ATI-OS needs at least 30GThat disk is too small. It needs 60 GB if the USB stick is over a year old, because it then has to compile everything
has mounted partitionsYou picked the USB stick, or something else is using that disk
is in use by: lvm (or raid, or crypt)The disk is part of a more complicated storage setup. You have to take that apart yourself first
no networkIt downloads during the install. Connect Wi-Fi with iwctl

It complains about signatures on the downloaded software

Two causes. The error message mentions neither.

  • The clock is wrong. A wrong date makes signatures look expired. Check with timedatectl.
  • The USB stick is old. Its built-in keys have expired. Rebuild it.

It took two hours instead of twenty minutes

The pre-compiled software was not used, and it says which:

  • no prebuilt AUR repository on this medium — the USB stick was made without running ./aur-repo.sh first.
  • medium is N days old — NOT using its prebuilt packages — deliberate. Over a year old, that software was built against libraries too different from today's to be trusted, so it compiles it fresh instead. Correct, and slow. Rebuild the stick.

Building the stick fails with "call to execv failed"

Your own computer's settings are leaking into the image. This project installs a safety check that runs before every software change, and it does not exist inside the fresh system being built. The error names neither the check nor the missing file.

Both build scripts prevent this. Seeing it means that protection was lost, or a configuration file was hand-edited.

One of the software packages will not build

Read that package's own log, not the summary:

ls ~/ati-os-build/logs/

The desktop itself

Every shortcut that opens a program suddenly fails

Browsers, terminal, file manager, Telegram. All of them. The log shows an error mentioning cmd_spawn.

Cause: an update to the window manager renamed something the settings file uses.

Fix: update this project's files, or edit the settings to use the new name.

I changed a setting and nothing happened

Press Super+Shift+r. Your windows stay where they are.

A lighter "reload" command exists, but only a full restart reliably picks up new software and new settings.

The bar shows an error where the battery should be

On a desktop with no battery. Fixed. The indicator is only added when a battery exists.

On some laptops the battery and charger have unusual internal names. The code looks at what each device is rather than what it is called. That fix was reasoned out, never tested on a laptop that names them that way. A wrong battery indicator is likely this.

The desktop freezes for a few seconds

Something is blocking the main loop, usually after a shortcut or a bar update. See Qtile freezes in the full file.

The six Alt shortcuts and hint mode do nothing

No error, nothing on screen. A missing dependency, not a broken shortcut. In the full file.

Colours

Telegram or the file manager is still the old colour

They read their colours once, at start. Close and reopen them. Still wrong? Log out and back in.

The startup screen is still the old colour

That one has to be rebuilt, which takes about a minute:

boot-splash sync

Folder icons never change colour

An optional package is missing. It fails silently by design rather than breaking the whole theme change.

Web pages are not dark

Deliberate. Rather than a filter over the top, the desktop tells websites you prefer dark mode, so each serves its own dark design. For a site with none, turn on force-dark for that one site in your browser's page menu.

Changing the wallpaper replaced my theme

Fixed. The wallpaper only changes your colours on the theme called Wallpaper. On any other, a new picture is only a new picture.

Other colour problems in the full file

  • The browser's toolbar follows the theme but its home page does not, or the reverse
  • The text editor's dashboard stays the default colour
  • The bar widgets keep old colours after a theme change
  • A new wallpaper is applied with the old colours
  • Rapid theme changes leave things half-applied
  • Every menu stops opening after a wallpaper change — while the theme change reported success
  • The theme step fails during install, before you have ever started the desktop

Text looks wrong

Everything is in a strange font and nothing lines up

What you see: the bar, popups and notifications in an odd font, with every column ragged. Nothing reports an error. It looks like broken layout code.

What it is: a missing font. The system never reports one. It silently substitutes, and here the substitute is a Chinese/Japanese/Korean face. This project lines its columns up with spaces, and spaces only line up in a fixed-width font.

Check it:

fc-match "JetBrainsMono Nerd Font"

It should answer with that same name. Anything else means the font is missing.

bash ~/.dotfiles/installScripts/validate.sh

Look at its UI fonts installed section, which checks every font the desktop names.

If you are adding a font to a settings file yourself

Two edits, not one. Add the package to modules/fonts.yaml and add the family name to the list in validate.sh. That list is hand-maintained.

Get the real family name with fc-list : family. They are rarely what you would guess. One package installs "FiraCode Nerd Font", not "FiraCode Nerd". This project has fallen into that twice.

Wi-Fi and Bluetooth

The pickers say the service is not running

What you see: Super+P then n or b opens and immediately errors, or the Bluetooth list never fills. The tray icons do nothing.

What it is: installing software is not the same as switching it on. Fix:

./wizard.sh --yes --only=radios

To check afterwards:

systemctl is-enabled NetworkManager.service bluetooth.service

Watch out for service_trim.sh. That optional tuning script offers to switch Bluetooth off. Say yes and the Bluetooth picker goes dead with no other symptom.

Connecting hangs forever

The busy indicator spins and never stops. Press c to give up. Connecting to an out-of-range Bluetooth device genuinely never finishes on its own.

A network keeps failing with a password I know is right

Fixed. A wrong password asks again rather than saving a network that can never connect. For an old broken entry, press x to forget it and connect again.

Other network problems in the full file

  • A separate password dialog pops up on top of the picker
  • The Bluetooth list fills up and then empties itself
  • The Wi-Fi QR code will not scan

The menus

Pressing Enter in the password list does nothing

The list opens, the entries are there, Enter closes it and copies nothing. In the full file, with two other password-tool problems.

Every confirmation answers "cancel" by itself

Only with more than one person on the computer. Fixed. The menus keep temporary state somewhere private to each user rather than in a shared location.

The translator shows no suggestions or examples

The missing AI key. Translation itself still works.

Other menu problems in the full file

  • The translator returns a single word with no dictionary
  • The flashcard tool builds a whole card and then cannot reach Anki
  • The saved-links list shows fewer links than the file has
  • The wallpaper menu lists nothing
  • Some PDFs report "file not found"
  • The process killer is slow to open, or its columns do not line up
  • The screenshot menu fails before it appears
  • The PDF tool silently does nothing
  • Webcam recording uses the wrong device or resolution

Dictation

It transcribes nonsense

Your microphone volume was reset to a distorting level. Something resets it at every login, and a background service puts it back. If dictation was fine and suddenly got much worse, this is why.

It is very slow

A few seconds of speech taking ten or more means the engine was installed unoptimised. An install step rebuilds it about 13 times faster. That step warns and skips itself rather than failing, so it may have been skipped quietly.

Live dictation types things I never said

Usually repeated phrases. The engine does not cleanly separate one phrase from the next in live mode, and there is a piece specifically to work around that. In the full file.

Errors when you open a terminal

A wall of errors on every new terminal

Unknown command, a temporary file that could not be created, a missing filename. All under Fish shell in the full file.

The terminal multiplexer ignores all its add-ons

tmux starts fine and quietly ignores every plugin line, so pane navigation and session-restore do nothing. Its add-on manager needs a one-time setup, which is an install step.

Warnings when the desktop starts that are not problems

Some startup messages mean nothing. The full file has an entry called "What qtile.log looks like on a clean restart", the fastest way to tell a real error from normal noise.

Finding the rest

The complete record is TROUBLESHOOTING.md in the project folder: 126 entries, each with what you see, what caused it and what to do.

Search it from the desktop: click the logo in the bar → Documentation → Troubleshooting. That list shows each entry by what you see rather than by a heading, so you can search the words you would actually type, and it jumps straight to the right place.
