Troubleshooting

Reorganised from TROUBLESHOOTING.md, which records 126 real cases as symptom → root cause → fix. The most likely ones are first.

The first five minutes

The install finished and I have a black screen with a blinking cursor

That is the install working. There is no display manager and no autologin, on purpose — the disable-dm module disables lightdm, gdm, sddm and lxdm.

  1. Log in with the username and password you chose.
  2. Type letsgo. If that says command not found, type startx.

letsgo is a fish function, so it only exists when the account's login shell is fish. The login-shell module does that with chsh, but skips itself if fish is not installed. On such a machine startx is the one that works.

startx says "Server is already active for display 0"

An unclean X exit left /tmp/.X0-lock behind. letsgo removes it for you and tells you it did. By hand:

pgrep -x Xorg          # if this prints a PID, X really is running -- Ctrl+Alt+F1
rm -f /tmp/.X0-lock    # only when it is not
startx

The desktop did not appear after the first ATI-OS boot

The wizard runs on first boot, not during the install. It takes about 20 minutes and prints its progress on screen. If it failed:

cat /var/log/ati-os-firstboot.log          # the whole run
cat /var/lib/ati-os/firstboot-complete     # the wizard's exit status
cd ~/.dotfiles/installScripts && ./wizard.sh

The marker records the exit status rather than merely that the run happened, so a failed first boot does not mark itself done and will retry.

validate.sh says everything passed but nothing works

validate.sh degrades every check it cannot run to "skipped" — so on a machine where the install failed and nothing is present, it skips everything and exits green. On a fresh machine, trust the wizard's summary card (46 ok / 0 failed) over validate.sh.

The desktop came up but it looks like stock qtile

qtile falls back to its built-in configuration when yours raises an error, and qtile cmd-obj -f status answers OK either way. Check the log for the fallback:

grep -i "config" ~/.local/share/qtile/qtile.log | head
bash ~/.dotfiles/installScripts/validate.sh   # loads the config for real

The one rule

On a clean install, the module that reports the failure is almost never the module at fault. One full disk once presented as five broken modules, 32 modules after the cause. One blocked pacman transaction presented as two. Read the per-module logs (/tmp/wizard-<id>.err), not the wizard's summary card — that is what distinguished five root causes from twenty-two symptoms.

The corollary, learned the same way: verify a check against a known-good case before trusting it. Five separate times in this repo's history the check was wrong rather than the code.

Install and first boot

The wizard finished but packages are missing

dcli sync prints "✓ Packages synced successfully" regardless of what happened above it. This has shown up for three unrelated root causes. Always verify:

dcli sync --dry-run    # after any large sync, if a binary seems missing

The three causes seen so far:

  1. The sudo credential cache expired mid-build. Packages show Finished making: X but never get pacman -U'd. install.sh now keeps sudo alive for the whole run.
  2. A hard package conflict blocked the entire batch. It is one pacman -U transaction, so every package in that round fails, not just the conflicting one. yay vs yay-bin did this; so did jack2 vs pipewire-jack, where the resolver picks jack2 for the virtual jack that ffmpeg/mpv/timidity depend on, and pacman aborts everything.
  3. A build-time tool failure inside one package's prepare(). rustup having no default toolchain broke every cargo-based AUR package (paru, didyoumean) and nothing else.

wizard.sh's dcli-sync module now self-verifies with a dry-run and retries. If you run dcli sync by hand, do the dry-run yourself.

The install ran out of disk

It needs about 25 GB installed, and considerably more transiently when AUR packages are compiled. This presented once as six failed modules all reporting No space left on device, starting 32 modules after the actual cause. The VM test now provisions 60 GB.

On a long-lived machine, ~/.cache/yay is worth checking: yay -Sc.

The install stopped on unread Arch news

informant refuses every pacman transaction until Arch news is read, and it installs itself mid-sync, so a fresh machine always has unread news. It presented as boot-splash (no plymouth) and the desktop check (no Xvfb) failing, 5 and 20 modules downstream.

The wizard marks the news read after the sync. Note that doing it as the invoking user does nothing — informant's pacman hook runs as root and checks root's read state.

The ATI-OS medium

The machine will not boot the USB stick at all

Three things, in this order:

  1. UEFI, not legacy/CSM. The boot menu usually shows each device twice; pick the entry that says UEFI. ATI-OS installs UEFI-only.
  2. Secure Boot off. ATI-OS ships an unsigned bootloader. The installer warns about this, but skip past it and the machine installs fine and then refuses to boot with "no bootable device" — which looks like a broken install and is not one.
  3. The write actually finished. dd returns before the data is on the stick unless you passed oflag=sync. Verify with sha256sum -c ati-os-*.iso.sha256.

"no bootable device" after the install finished

Almost always Secure Boot, above. If it is genuinely off, check the boot entry:

# from the live medium, with the installed disk mounted at /mnt
cat /mnt/boot/loader/entries/ati-os.conf
blkid -o value -s PARTUUID /dev/sdaX      # must match root=PARTUUID=

test-iso.sh asserts exactly this comparison, so a mismatch means the install did not finish rather than that it was written wrong.

The installer refuses to start

MessageMeaning
booted in BIOS/legacy modeUEFI only — see above
${N}G — ATI-OS needs at least 30GThe disk is too small. 60 G if the medium is over a year old, because the AUR set then gets compiled and its build trees are large
has mounted partitionsYou picked the USB stick, or something else is using that disk
is in use by: lvm/raid/cryptDeactivate it first: vgchange -an, mdadm --stop, cryptsetup close
no networkIt downloads during the install. Wi-Fi: iwctl

Package signature errors during the install

Two causes, and the message names neither.

  • A wrong clock. Signatures then look expired or not-yet-valid. The installer syncs the clock via NTP before installing anything; if that failed it says so. Check timedatectl.
  • An old medium. pacstrap builds the new system's keyring from the keys on the stick. The installer refreshes archlinux-keyring from the network first, so this should not happen — but with no network at that moment it cannot, and falls back to what shipped. Rebuild the ISO.

The install took two hours instead of twenty minutes

The prebuilt AUR packages were not used, and the installer says which:

  • no prebuilt AUR repository on this medium — the ISO was built without running aur-repo.sh first.
  • medium is N days old — NOT using its prebuilt packages — deliberate. Over a year, those binaries were compiled against libraries too old to trust against today's glibc, so they are compiled from source instead. Correct, and slow. Rebuild the ISO.

Building the ISO fails with "call to execv failed"

The host's own pacman hooks are leaking into the image being built. This repo installs /etc/pacman.d/hooks/00-preflight.hook, which runs /usr/local/bin/pacman-preflight — a file that exists on the build machine and in no fresh root anywhere. pacman reports it as:

call to execv failed (No such file or directory)
error: failed to commit transaction (failed to run transaction hooks)

naming neither the hook nor the missing file. Both aur-repo.sh and build-iso.sh override HookDir to an empty directory to prevent it. Seeing this means that override was lost or the config was hand-edited.

An AUR package will not build

aur-repo.sh writes one log per package to ~/ati-os-build/logs/. Read that one, not the summary. Two cases already handled, in case they resurface:

  • You appear to have cloned an empty repository — the AUR repo is named after the package base, not the package. espanso-x11 lives in espanso.
  • built but produced no package — a PKGBUILD overrode PKGEXT. pacman-static ships .pkg.tar.xz, not .zst.

The desktop

Every app-launching keybind crashes with cmd_spawn

Symptom: browser toggles, terminal, file manager, Telegram and Obsidian all fail with AttributeError: 'Qtile' object has no attribute 'cmd_spawn' in ~/.local/share/qtile/qtile.log.

Cause: a pacman -Syu upgraded qtile itself, which removed Qtile.cmd_spawn() in favour of Qtile.spawn() — same signature, a drop-in rename. Fix: mechanical rename of every qtile.cmd_spawn( call site.

Newly-installed packages or config do not take effect after reload_config

Use Super+Shift+r (a full restart) rather than reload_config. The restart preserves window→group and layout state through qtile's own pickle serialisation; reload_config loses layout order and can re-shuffle Match'd applications back to their default group.

Six Alt bindings and the whole Hint-Mode chord do nothing

The Homerow hint keys are dead with no error. This is in the full file under Qtile config; it is a dependency problem, not a binding problem.

The bar shows an error where the battery should be

Error: Unable to read status for status_file, permanently, on a desktop with no battery. The battery chip is now only added to the bar when a battery actually exists. Related: battery-events finds the battery and adapter by type in /sys rather than by name, because BAT0/AC is what one laptop happens to call them — others use BAT1, ACAD, ADP0, ADP1 or AC0.

The BAT1/ADP1 fix is reasoned from /sys semantics, never observed on a laptop that names them that way.

qtile freezes for seconds after a keybind or widget update

Something is blocking the main loop. See Qtile freezes in the full file.

Theming

Everything renders in a CJK face and every aligned column is ragged

Symptom: on a fresh install the bar, every popup and the notifications come up in a wrong-looking proportional face, and columns that were supposed to line up are ragged. Nothing errors and no log line mentions fonts. It reads like the layout code is broken.

Cause: fontconfig never errors on a missing family. It substitutes, silently, and on this system fc-match answers Noto Sans CJK KR for anything it does not have. Every padded column in this repo is aligned with spaces, and spaces only align in a monospace font.

fc-match "JetBrainsMono Nerd Font"   # must answer itself, not Noto
bash ~/.dotfiles/installScripts/validate.sh   # the "UI fonts installed" check

Adding a font to any config takes two edits. Declare the package in modules/fonts.yaml and add the family to the list in validate.sh's UI fonts installed check — that list is hand-maintained and does not derive itself. fc-list : family gives the real names; they are rarely what you would guess (ttf-firacode-nerd installs FiraCode Nerd Font, not FiraCode Nerd — a trap this repo has fallen into twice).

A wallpaper switch half-applies and the desktop never reloads

Several distinct cases sit under this symptom in the full file, and they are worth reading individually. The one to check first: every rofi menu stopping after a wallpaper change, with the theme switch reporting success.

Changing the wallpaper silently replaced my preset theme

Fixed, and now deliberate: the wallpaper only re-derives the palette when the active mode is already wal. On a preset, a new wallpaper swaps the desktop image and nothing else. See Wallpaper vs. theme.

Qt apps (Telegram, pcmanfm-qt) stay light or ignore the palette

Qt ignores the GTK theme entirely. It needs QT_QPA_PLATFORMTHEME=qt6ct, exported from .xinitrc, and it reads the palette at application start — so a fresh X session is required after a theme change.

Chrome follows the palette but Chromium does not, or vice versa

Both are in the full file, with different causes. The extension id is derived from browser-theme.pem at runtime because it is per-machine, and the browsers have to relaunch through their /usr/bin wrapper for *-flags.conf to apply.

  • nvim dashboard header stays default cyan
  • eww widgets keep doom-one colours after a theme switch
  • qtile popup cheatsheets stuck on doom-one

Network and Bluetooth

Fresh install: the WiFi/Bluetooth popups say the daemon is not running

Symptom: Super+P then n or b opens the popup and immediately errors — NetworkManager is not running, or an empty Bluetooth list that never fills. nm-applet and blueman-applet are visible in the tray and do nothing.

Cause: declaring a package installs a binary, not a running daemon. networkmanager and bluez are declared and installed, but for a long time nothing enabled the units. They were enabled on the development machine only because archinstall did it — exactly the kind of difference a package audit cannot see.

./wizard.sh --yes --only=radios
systemctl is-enabled NetworkManager.service bluetooth.service

The radios module is idempotent. Its uninstaller is a deliberate no-op: disabling NetworkManager to "reverse" an install leaves a machine with no network and no GUI to fix it with.

Watch out for service_trim.sh. It offers to disable bluetooth.service; say yes and the Super+P b picker goes dead with no other symptom.

A network stays "saved" with a password that can never work

Fixed: a wrong PSK re-asks rather than leaving a saved profile that can never connect.

Connecting to an out-of-range network or device hangs forever

The busy bar spins and never stops. Press c to cancel — bluetoothctl connect genuinely never returns for an out-of-range device.

Other network cases in the full file

  • Typing a WiFi password pops nm-applet's own GTK dialog on top of the popup
  • The Bluetooth list fills up, then empties itself a few seconds later
  • The QR code from the WiFi popup will not scan

The rofi menus

Every confirmation dialog answers "cancel" by itself, on a second account

On a machine with more than one user, one account's rofi state was in a fixed /tmp path owned by whoever got there first. All of those now route through ${XDG_RUNTIME_DIR:-/tmp/rofi-$(id -u)}.

Pressing Enter in rofi_pass does nothing at all

The picker opens, entries are listed, Enter closes it and nothing is copied. In the full file under Rofi, together with two other rbw cases: entries created with an empty password, and "multiple entries found" on get/remove/edit.

Vaultwarden web vault 404s while the API works

http://127.0.0.1:8222/api/config returns 200 but / does not. See the full file. Remember the web vault also requires https.

Other rofi cases in the full file

  • The translator returns only one word, with no dictionary popup
  • The translator and rofi_anki show empty synonyms and examples (this is the missing GEMINI_API_KEY)
  • rofi_anki builds a whole card, then fails at "Cannot reach AnkiConnect"
  • The shared-links picker shows fewer links than the file holds
  • The wallpaper picker (dm-setbg) lists nothing
  • dm-documents: "file not found" for some PDFs but not others
  • rofi-kill: slow to open, misaligned dividers, kill that did not kill, confirm defaulting to No, or no confirm at all
  • The screenshot picker fails before the menu even shows
  • rofi_ilovepdf silently does nothing (missing zenity / libreoffice)
  • Webcam recording ignores the resolution you picked, or records the wrong device
  • tailscale cert fails: "account does not support getting TLS certs" — MagicDNS and HTTPS Certificates both have to be enabled in the admin console

Voice dictation

The mic transcribes garbage, or a session is suddenly much worse than the last one

WirePlumber resets the mic capture gain to clipping levels on every login. The mic-gain module enables fix-mic-gain.service, which reasserts it.

voice_dictate feels much slower than it should

Transcribing a few seconds takes 10+ seconds when whisper-cli comes from the unoptimised AUR build. The whisper-fast module rebuilds it optimised and shadows the AUR binary via /usr/local — roughly 13× faster. It warns and skips rather than failing if it cannot, since it is a speedup, not a requirement.

voice_dictate_live types things you never said

Repeated phrases. whisper-stream's VAD sliding-window mode does not emit one clean block per finished phrase; voice_dictate_live_typer.py exists to type only the new words of each block.

Shell and session

A wall of errors on every new fish shell

Unknown command: colorscript, mktemp: failed to create file via template '~/tmp/.psub.XXXXXX', a Rust panic Broken pipe, source: missing filename argument. All covered under Fish shell in the full file. The image-envs module is what ensures ~/tmp exists.

tmux ignores every plugin

tmux starts fine and silently ignores every set -g @plugin line, so vim-tmux-navigator's pane navigation and resurrect/continuum's save and restore all do nothing. TPM needs a bootstrap; that is the tmux-tpm module, and it runs as part of the install.

Warnings on every qtile start that are not problems

  • xauth: (stdin):2: unknown command "<32 hex chars>" right after letsgo — the very first line, before the Xorg banner.
  • WARNING:libqtile:Key spec duplicated, overriding previous: <Key ([], Escape)> — this one was fixed by dropping qtile's auto-added Escape before appending the config's own, so it should no longer appear.
  • xkbcomp warnings about unresolved XF86… keysyms and <FK23>/<FK24> being redefined.

The full file has a "What qtile.log looks like on a clean restart" entry, which is the fastest way to tell a real error from noise.
